Preguntas cortas

Pregunta 1 · 0,5 puntos
¿Qué es un hilo? ¿Para qué se suele utilizar?

Hilo: secuencia única de control de flujo dentro de un programa; es la unidad de código más pequeña que se puede ejecutar.

Para qué se utiliza:

  • Ejecutar tareas lentas (conexiones de red, grabación en disco).
  • No paralizar el programa principal mientras se ejecutan otras tareas.
  • Evitar bloqueos inaceptables o indefinidos de un proceso.
  • Realizar múltiples tareas a la vez (p. ej. un servidor atendiendo a varios clientes).
Pregunta 2 · 1 punto
Ventajas de la computación distribuida.

Un sistema distribuido es un conjunto de computadores independientes, conectados por red, que colaboran en una tarea (no comparten memoria ni espacio de ejecución). Ventajas:

  • Económica: los computadores y el acceso a red son baratos.
  • Compartición de recursos.
  • Escalabilidad: se añaden máquinas según crece la carga.
  • Tolerancia a fallos: si un nodo cae, otros pueden seguir.

Como contrapunto (suma si lo mencionas): múltiples puntos de fallo y aspectos de seguridad.

Pregunta 3 · 1,5 puntos
Características del protocolo HTTP. ¿Cuál es la estructura de un paquete HTTP?

Características:

  • Hyper Text Transfer Protocol (RFC 1945), basado en URL: objeto al que se le pide la ejecución de un método y se obtiene un resultado según los parámetros.
  • Protocolo de solicitud-respuesta basado en texto: el cliente pide una acción y el servidor envía el resultado.
  • Utilizado por el 100 % de usuarios y servidores. No es lo mismo que HTML.
  • Sin estado: no recuerda peticiones anteriores (solución: cookies).
  • Muy genérico: permite definir tus propios comportamientos. Métodos: GET, POST, PUT, DELETE…

Estructura del mensaje (petición o respuesta):

  1. Primera línea: en la petición, método + recurso (URL) + versión (GET /index.html HTTP/1.0); en la respuesta, versión + código de estado + frase (HTTP/1.0 404 Not Found).
  2. Cabeceras: pares campo:valor acabados en CRLF (metainformación, p. ej. el tamaño del cuerpo).
  3. Línea en blanco (CRLF) que separa cabecera y cuerpo.
  4. Cuerpo (entity body): información extra / datos.

Preguntas de programación

Pregunta 4 · 0,5 puntos

Dada la siguiente clase:

public class Servidor {
    public static final int PUERTO = 8000;

    public void ejecutar() {
        try {
            ServerSocket serverSocket = new ServerSocket(Servidor.PUERTO);
            System.out.println("Esperando cliente...");
            Socket socket = serverSocket.accept();

            BufferedReader br = new BufferedReader(
                    new InputStreamReader(socket.getInputStream()));

            while (true) {
                System.out.println(br.readLine());
            }
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            System.out.println("Fin de servidor");
        }
    }

    public static void main(String[] args) {
        (new Servidor()).ejecutar();
    }
}

¿Cuál es el motivo para que salte la siguiente excepción al ejecutar dos veces seguidas el programa?

java.net.BindException: Address already in use
    at java.base/sun.nio.ch.Net.bind0(Native Method)
    at java.base/sun.nio.ch.Net.bind(Net.java:565)

La primera ejecución sigue viva y mantiene ocupado el puerto 8000: el servidor nunca termina porque está en un while(true) y nunca cierra el ServerSocket. Al lanzar la segunda, new ServerSocket(8000) no puede hacer el bind() a un puerto que ya está en uso → BindException: Address already in use.

Solución: parar la primera ejecución antes de lanzar la segunda, usar otro puerto, o cerrar el ServerSocket (try-with-resources).

Extra: cuando el cliente se desconecta, readLine() devuelve null y el bucle while(true) imprimiría «null» sin parar. Mejor: while ((linea = br.readLine()) != null).
Pregunta 5 · 0,5 puntos

Dadas las dos clases:

public class Main {
    public static void main(String[] args) {
        MiHilo miHilo = new MiHilo();

        System.out.println("Lanzamos hilos");
        for (int i = 0; i < 10; i++) {
            (new Thread()).start();
        }
        System.out.println("Hecho");
    }
}

public class MiHilo implements Runnable {
    @Override
    public void run() {
        System.out.println("Hola Mundo");
    }
}

¿Cuál es el motivo para que por consola salga lo siguiente y no aparezca el texto «Hola Mundo» repetido diez veces?

Lanzamos hilos
Hecho

Porque se crean hilos con new Thread() sin pasarles el Runnable. Un Thread sin Runnable tiene un run() vacío, así que start() lanza hilos que no hacen nada. El objeto miHilo se crea pero nunca se ejecuta.

// Corrección
for (int i = 0; i < 10; i++) {
    (new Thread(miHilo)).start();   // le pasamos el Runnable
}

Nota: MiHilo implements Runnable no extiende Thread, por eso no puede hacerse miHilo.start(): hay que envolverlo en un Thread.

Pregunta 6 · 0,5 puntos

Dadas las siguientes clases:

public class HiloContador implements Runnable {
    private int contador = 0;

    @Override
    public void run() {
        for (int i = 0; i < 1000; i++) {
            contador++;
            System.out.println("Contador: " + contador);
        }
    }
}

public class Principal {
    public static void main(String[] args) {
        HiloContador hc = new HiloContador();
        for (int i = 0; i < 5; i++) {
            new Thread(hc).start();
        }
    }
}

¿Por qué el valor mostrado del contador no es 5000, sino un número menor y variable en cada ejecución?

Los 5 hilos comparten el mismo objeto hc y por tanto la misma variable contador. contador++ no es atómico (leer → sumar → escribir): dos hilos pueden leer el mismo valor y escribir ambos el mismo resultado, perdiéndose incrementos. Es una condición de carrera, y por eso el resultado es menor que 5000 y distinto en cada ejecución (depende de cómo planifique el SO los hilos).

// Solución: acceso exclusivo al incremento
private synchronized void incrementa() { contador++; }
// o bien: private AtomicInteger contador = new AtomicInteger();   // contador.incrementAndGet()

(El println dentro del bucle además mezcla la salida de los hilos, pero la causa del fallo es la falta de sincronización.)

Pregunta 7 · 0,5 puntos

Dada la siguiente clase (paquete ucam.examen.daduno):

public class Main {
    public static void main(String[] args) {
        MiHilo miHilo = new MiHilo();

        // Lanzamos diez hilos
        for (int i = 0; i < 10; i++) {
            miHilo.start();
        }
        // Mostramos mensaje de fin
        System.out.println("Fin del programa");
    }
}

¿Por qué salta la siguiente excepción?

Exception in thread "main" java.lang.IllegalThreadStateException
    at java.base/java.lang.Thread.start(Thread.java:800)
    at src/ucam.examen.daduno.Main.main(Main.java:11)

Porque se llama a start() varias veces sobre el mismo objeto (miHilo). Un hilo solo se puede arrancar una vez; en la segunda iteración el hilo ya está arrancado (o terminado) y start() lanza IllegalThreadStateException.

// Corrección: un objeto hilo nuevo por cada lanzamiento
for (int i = 0; i < 10; i++) {
    MiHilo miHilo = new MiHilo();
    miHilo.start();
}

Pregunta de desarrollo

Pregunta 8 · 5 puntos

El equipo de desarrollo de nuestra empresa está trabajando en un sistema de gestión de fichaje de empleados al que se pueden conectar los clientes mediante el uso de Sockets. El jefe de equipo nos ha pedido que implementemos, dentro del servidor, el hilo de ejecución que gestiona los comandos recibidos. En concreto se trata de implementar solamente la clase HiloGestionFichaje para que al recibir el comando y procesarlo devuelva el resultado correspondiente. Esta clase tiene un atributo, Socket, que representa el canal de comunicación con el cliente. Habrá que crear los buffers correspondientes y leer/escribir de los mismos.

Los comandos que implementará el servidor serán los siguientes:

FunciónDescripción
ALTAEMPLEADO
ALTAEMPLEADO idEmpleado nombreCompleto		Añade un empleado al sistema con ese identificador y nombre. Devuelve una cadena de texto indicando si se ha introducido correctamente el empleado o si se ha producido un error.
Ej.: ALTAEMPLEADO 1234 Juan Martínez
→ Ok. Empleado insertado
→ Error. El empleado ya existe
ENTRADA
ENTRADA idEmpleado		Registra la entrada del empleado usando la hora del servidor. Devuelve una cadena con el resultado de la operación.
Ej.: ENTRADA 1234
→ Ok. Entrada registrada. 2025-11-11T17:05
→ Error. El empleado ya ha registrado la entrada
SALIDA
SALIDA idEmpleado		Registra la salida del empleado usando la hora del servidor. Devuelve una cadena con el resultado de la operación: ok o error.
Ej.: SALIDA 1234
→ Ok. Salida registrada. 2025-11-11T19:05
→ Error. El empleado no tiene registrada entrada
HORAS
HORAS idEmpleado		Devuelve el total de horas trabajadas acumuladas por el empleado.
Ej.: HORAS 1234
→ Ok. Juan tiene trabajadas 2 horas.
ESTADO
ESTADO idEmpleado		Informa del estado actual del empleado: si tiene o no una entrada abierta y, en su caso, desde cuándo.
Ej.: ESTADO 1234
→ El empleado ha registrado entrada: 2025-11-11T17:05
→ El empleado no ha registrado entrada

Condiciones: para cada envío el sistema debe comprobar si el empleado ya existe. Para simplificar la gestión, el listado de empleados se podrá almacenar como atributo en la clase implementada. Se recomienda la creación de una clase Empleado que almacene la información del mismo. No se puede FICHAR_ENTRADA si ya hay entrada abierta. No se puede FICHAR_SALIDA si no hay entrada abierta.

Se supone que existe una clase GestionFechas que tiene los siguientes métodos estáticos:

  • getHoraActual() → devuelve un objeto de la clase Timestamp con la fecha y hora actual.
  • getHorasEntre(Timestamp fechaInicio, Timestamp fechaFin) → devuelve un número con un decimal (float) que representa las horas que han pasado entre las dos fechas que se pasan como parámetro.
  • getTexto(Timestamp fecha) → devuelve la cadena de texto que representa a la fecha que recibe por parámetro.

Plan: (1) clase Empleado con id, nombre, Timestamp de la entrada abierta (null si no hay) y horas acumuladas; (2) HiloGestionFichaje extends Thread con el Socket, el listado de empleados, los buffers y un switch sobre el comando; (3) un método por comando, comprobando siempre las condiciones del enunciado.

Clase Empleado

import java.sql.Timestamp;

public class Empleado {
    private String id;
    private String nombre;
    private Timestamp entrada;      // null si no hay entrada abierta
    private float horasAcumuladas = 0;

    public Empleado(String id, String nombre) {
        this.id = id;
        this.nombre = nombre;
    }
    public String getId() { return id; }
    public String getNombre() { return nombre; }
    public Timestamp getEntrada() { return entrada; }
    public void setEntrada(Timestamp entrada) { this.entrada = entrada; }
    public boolean tieneEntradaAbierta() { return entrada != null; }
    public float getHorasAcumuladas() { return horasAcumuladas; }
    public void sumaHoras(float horas) { this.horasAcumuladas += horas; }
}

Clase HiloGestionFichaje (la que se pide)

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.net.Socket;
import java.sql.Timestamp;
import java.util.Hashtable;

public class HiloGestionFichaje extends Thread {
    // Listado de empleados (compartido por todos los hilos -> accesos synchronized)
    private static Hashtable<String, Empleado> empleados = new Hashtable<String, Empleado>();

    private Socket socket;
    private BufferedReader br;
    private PrintWriter pw;

    public HiloGestionFichaje(Socket socket) {
        this.socket = socket;
    }

    @Override
    public void run() {
        try {
            // Buffers de comunicacion con el cliente
            this.br = new BufferedReader(new InputStreamReader(this.socket.getInputStream()));
            this.pw = new PrintWriter(new OutputStreamWriter(this.socket.getOutputStream()));

            String linea;
            while ((linea = this.br.readLine()) != null) {
                String respuesta = this.procesar(linea);
                this.pw.println(respuesta);
                this.pw.flush();
            }
        } catch (IOException e) {
            System.out.println("Conexion finalizada");
        } finally {
            try { this.socket.close(); } catch (IOException e) { }
        }
    }

    private String procesar(String linea) {
        String[] partes = linea.trim().split(" ", 3);   // 3: el nombre completo puede llevar espacios
        String comando = partes[0].toUpperCase();

        switch (comando) {
        case "ALTAEMPLEADO":
            if (partes.length < 3) return "Error. Uso: ALTAEMPLEADO idEmpleado nombreCompleto";
            return this.altaEmpleado(partes[1], partes[2]);
        case "ENTRADA":
            if (partes.length < 2) return "Error. Uso: ENTRADA idEmpleado";
            return this.entrada(partes[1]);
        case "SALIDA":
            if (partes.length < 2) return "Error. Uso: SALIDA idEmpleado";
            return this.salida(partes[1]);
        case "HORAS":
            if (partes.length < 2) return "Error. Uso: HORAS idEmpleado";
            return this.horas(partes[1]);
        case "ESTADO":
            if (partes.length < 2) return "Error. Uso: ESTADO idEmpleado";
            return this.estado(partes[1]);
        default:
            return "Error. Comando no reconocido";
        }
    }

    private synchronized String altaEmpleado(String id, String nombre) {
        if (empleados.containsKey(id)) {
            return "Error. El empleado ya existe";
        }
        empleados.put(id, new Empleado(id, nombre));
        return "Ok. Empleado insertado";
    }

    private synchronized String entrada(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        if (e.tieneEntradaAbierta()) {
            return "Error. El empleado ya ha registrado la entrada";
        }
        Timestamp ahora = GestionFechas.getHoraActual();
        e.setEntrada(ahora);
        return "Ok. Entrada registrada. " + GestionFechas.getTexto(ahora);
    }

    private synchronized String salida(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        if (!e.tieneEntradaAbierta()) {
            return "Error. El empleado no tiene registrada entrada";
        }
        Timestamp ahora = GestionFechas.getHoraActual();
        e.sumaHoras(GestionFechas.getHorasEntre(e.getEntrada(), ahora));
        e.setEntrada(null);                              // cierra la entrada abierta
        return "Ok. Salida registrada. " + GestionFechas.getTexto(ahora);
    }

    private synchronized String horas(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        return "Ok. " + e.getNombre() + " tiene trabajadas " + e.getHorasAcumuladas() + " horas.";
    }

    private synchronized String estado(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        if (e.tieneEntradaAbierta()) {
            return "El empleado ha registrado entrada: " + GestionFechas.getTexto(e.getEntrada());
        }
        return "El empleado no ha registrado entrada";
    }
}

import java.io.IOException;
import java.net.ServerSocket;
import java.net.Socket;

public class Servidor {
    public static final int PUERTO = 8000;

    public void ejecutar() {
        try (ServerSocket serverSocket = new ServerSocket(PUERTO)) {
            System.out.println("Esperando clientes...");
            while (true) {
                Socket socket = serverSocket.accept();
                new HiloGestionFichaje(socket).start();   // un hilo por cliente
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    public static void main(String[] args) {
        (new Servidor()).ejecutar();
    }
}
Qué mira el corrector: buffers bien creados (BufferedReader/PrintWriter + flush()) · bucle de lectura · split y switch · alta rechaza duplicados · ENTRADA rechazada si ya hay entrada · SALIDA rechazada si no hay entrada y suma horas con getHorasEntre · HORAS · ESTADO con getTexto · mensajes exactamente como el enunciado.
Detalles: split(" ", 3) porque el nombre completo lleva espacios; el listado es static + synchronized porque lo comparten todos los hilos (varios clientes); se añade «El empleado no existe» para ENTRADA/SALIDA/HORAS/ESTADO de un id desconocido (el enunciado dice que se debe comprobar si existe).
