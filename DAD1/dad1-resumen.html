1. Computación distribuida (Tema 1.1)

Concepto de sistema distribuido

Sistema distribuido: conjunto de computadores independientes, interconectados a través de una red, que son capaces de colaborar para realizar una tarea.

  • Computadores independientes: no comparten memoria ni espacio de ejecución.
  • Monoprocesador: una única unidad central de proceso (el modelo anterior).
  • Computación distribuida: la computación que se lleva a cabo en un sistema distribuido.
  • Servicio de red: lo proporciona un tipo especial de programa (servidor) en la red. Ej.: WWW, FTP, POP3.
  • Aplicación de red: aplicación para usuarios finales ejecutada en ordenadores conectados por red.

Un poco de historia

  • Años 60: primera conexión para compartir ficheros.
  • 1972: primer correo electrónico en ARPANET.
  • 1985: File Transfer Protocol (FTP).
  • Finales de los 80: World Wide Web.
  • Los protocolos se documentan en RFC (Request For Comments).

Ventajas e inconvenientes

VentajasInconvenientes
Los computadores y el acceso a red son económicosMúltiples puntos de fallo
Compartición de recursosAspectos de seguridad
Escalabilidad
Tolerancia a fallos

Formas de computación

FormaDescripción
MonolíticaUn único computador sin conexión y un solo usuario. (Mainframe: varios usuarios en un único ordenador, cada uno con su sesión.)
DistribuidaMúltiples computadores conectados por red.
ParalelaMás de un procesador simultáneamente para ejecutar un programa. Es difícil dividir un programa en porciones. Ej.: biología, aeronáutica, IA.
CooperativaDividir la computación entre ordenadores conectados para aprovechar los ciclos de CPU excedentes.
Dicho por el profe: distribuida = muchos computadores; paralela = uso de varios procesadores.

2. Comunicación entre procesos - IPC (Tema 1.2)

Conceptos básicos

  • Sistema distribuido = comunicación entre procesos (IPC): procesos separados e independientes se comunican para colaborar en una tarea (emisor → datos → receptor).
  • Es necesario un protocolo: ¿quién es el emisor? ¿quién el receptor?
  • Unicast: de un proceso a otro. Multicast: de un proceso a varios.
  • El SO ofrece colas de mensajes, semáforos y regiones de memoria compartida; suele haber un nivel de abstracción sobre el SO.

Operaciones primitivas (interfaz básica)

OperaciónQué hace
EnviarEn el emisor: transmite datos hacia el receptor.
RecibirEn el receptor.
ConectarUn proceso invoca solicitar-conexión y el otro aceptar-conexión.
DesconectarLibera ambos extremos.

Los procesos invocan estas operaciones de forma independiente; cada invocación implica la ocurrencia de un evento.

Sincronización de eventos

  • Los extremos son independientes: ¿cómo saber que ha terminado? Lo más sencillo: peticiones bloqueantes.
  • Operaciones bloqueantes = síncronas; no bloqueantes = asíncronas. Ej.: petición web = síncrona; respuesta del servidor = asíncrona.
  • Si no se produce el desbloqueo → bloqueo indefinido.
CombinaciónComportamiento
Enviar síncrono + recibir síncronoAmbos se bloquean; la librería IPC da un asentimiento transparente. Termina enviar cuando llega el dato y termina recibir.
Enviar asíncrono + recibir síncronoEl emisor sigue sin esperar; el receptor se bloquea hasta que llegan los datos.
Enviar síncrono + recibir asíncronoEscenario 1: recibir lanzado antes y datos ya disponibles → asentimiento. Escenario 2: el recibir ya retornó vacío y el envío bloqueante nunca se desbloquea → bloqueo indefinido. Escenario 3: se notifica al proceso la llegada de datos.
Enviar asíncrono + recibir asíncronoNadie se bloquea; al receptor se le notifica la llegada de los datos.

Bloqueo indefinido: dos soluciones

  1. Temporizadores (timers): límite de tiempo de espera de una operación; evitan quedarse bloqueado si la respuesta no llega.
  2. Proceso hijo o hilo de ejecución: el programa realiza varias tareas a la vez; útil para tareas lentas (conexiones de red, grabar en disco).

3. Hilos de ejecución en Java

Qué es un hilo y para qué sirve

Hilo: secuencia única de control de flujo dentro de un programa; la unidad de código más pequeña que se puede ejecutar.

Ventajas / usos:

  • Ejecución de tareas lentas.
  • No paralizar el programa principal mientras se ejecutan otras tareas.
  • Evitar bloqueos inaceptables (un bloqueo indefinido se mitiga con hilos).
  • Manejo de múltiples tareas a la vez.

Dos formas de crear un hilo

FormaPasos
Heredar de ThreadClase que extends Thread → implementar run() → crear el objeto y llamar a start().
Implementar RunnableClase que implements Runnable → implementar run() → new Thread(objeto).start().
// 1) Heredando de Thread
public class MiHilo extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) {
            System.out.println("Ejecución: " + i);
            try { Thread.sleep(500); } catch (InterruptedException e) { e.printStackTrace(); }
        }
    }
}
// uso:  MiHilo h = new MiHilo(); h.start();

// 2) Implementando Runnable
public class MiHilo implements Runnable { /* mismo run() */ }
// uso:  Thread t = new Thread(new MiHilo()); t.start();
Errores clásicos de examen:
  • run() en vez de start() → se ejecuta en el hilo actual, no se crea un hilo nuevo.
  • Llamar start() dos veces sobre el mismo objeto → IllegalThreadStateException. Hay que crear un objeto nuevo por hilo.
  • new Thread().start() con un Runnable sin pasárselo → el hilo no hace nada: hay que hacer new Thread(miRunnable).
  • No puedes crear objetos de interfaces (new Runnable() sin implementarla no vale).

Métodos útiles

MétodoPara qué
start()Lanza el hilo (ejecuta run() en paralelo).
Thread.sleep(ms)Duerme el hilo actual; lanza InterruptedException.
join() / join(ms)El hilo que lo llama espera a que termine el otro (o a que pase el tiempo indicado).
interrupt()Interrumpe el hilo: si duerme/espera salta InterruptedException.
UnHilo unHilo = new UnHilo();
unHilo.start();
unHilo.join(5000);      // main espera como máximo 5 s
// unHilo.interrupt();  // para forzar la parada si sigue dormido

Condición de carrera y synchronized

Si varios hilos modifican la misma variable compartida (contador++ no es atómico: leer-sumar-escribir), se pisan y el resultado es menor y variable en cada ejecución (p. ej. 5 hilos × 1000 ≠ 5000).

public class Contador {
    private int total = 0;
    public synchronized void sumaUno() {   // solo un hilo a la vez
        this.total = this.total + 1;
    }
    public int getTotal() { return this.total; }
}
Alternativas: AtomicInteger, o un bloque synchronized(objeto) { ... }.

Parar un hilo desde una interfaz Swing (taller)

  • El hilo (HiloContador extends Thread) tiene un atributo running que comprueba en el bucle; un método lo pone a false para pararlo.
  • Un JComboBox comboHilos guarda los hilos lanzados; ActionLanzarHilo crea y arranca uno; ActionPararHilo toma getSelectedItem() y lo para.
  • Para quitarlo de la lista: comboHilos.removeItem(comboHilos.getSelectedItem()).
  • porDondeVoy: contador static para dar un id único a cada hilo.

4. Sockets (Tema 2.2)

Concepto

Socket: punto de conexión entre dos procesos, identificado por una IP y un puerto.

Para comunicarse hace falta un objeto de la clase Socket en cada extremo. Los dos puertos (servidor y cliente) identifican la comunicación. Tiene que haber un protocolo.

Proceso de conexión

ServidorCliente
socket(): crear socketsocket(): crear socket
bind(): asocia el socket a un puerto del SO (lo especificamos nosotros)bind(): se le asigna un puerto (aleatorio, lo genera el programa)
listen(): permite que se conecten a nuestra máquina
accept(): acepta la petición entrante (se bloquea hasta que llega un cliente)(se conecta)
leer() / escribir()escribir() / leer()
¿Cómo se activa un socket? → con accept() (el servidor se queda esperando y continúa cuando el cliente se conecta).

Clases en Java

ClaseMétodos clave
SocketSocket(String host, int puerto), getInputStream(), getOutputStream(), close()
ServerSocketServerSocket(int puerto), accept() (devuelve un Socket con ese cliente)
  • El servidor no necesita IP (la máquina es él); el puerto debe ser el mismo en cliente y servidor, si no no hay conexión.
  • BufferedReader (readLine()) = leer; PrintWriter (println() + flush()) = escribir.
  • InputStreamReader convierte bytes a caracteres; OutputStreamWriter caracteres a bytes.
  • Ojo con el orden: ServerSocket → accept() → buffers.

Primer ejemplo: cliente y servidor

Servidor

package edu.ucam.sockets.primersocket;

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;

public class Servidor {

    public void ejecutar() {
        
        try {
            ServerSocket serverSocket = new ServerSocket(5000);
            
            System.out.println("Servidor lanzado esperando cliente...");
            
            Socket socket = serverSocket.accept();
            
            PrintWriter pw = new PrintWriter(new OutputStreamWriter(socket.getOutputStream()));
            BufferedReader br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
            
            
            String linea = br.readLine();
            
            System.out.println("Linea recibida en servidor: " + linea);
            
            pw.println("Te la devuelvo " + linea);
            pw.flush();
                
            
        } catch (IOException e) {
            // TODO Auto-generated catch block
            e.printStackTrace();
        }
        
        
    }
    
    public static void main(String[] args) {
        (new Servidor()).ejecutar();

    }

}

Servidor multihilo (varios clientes a la vez)

Con un único hilo, el servidor queda atrapado atendiendo al primer cliente. Solución: el main solo hace accept() y por cada cliente lanza un hilo (HiloServidor extends Thread) que recibe el socket y lleva la conversación en su run().

// Servidor.java
while (true) {
    Socket socket = serverSocket.accept();      // espera cliente
    new HiloServidor(socket).start();           // un hilo por cliente
}
BindException: Address already in use → ya hay otro proceso (normalmente una ejecución anterior del servidor que sigue viva) usando ese puerto. Párala o cambia de puerto. En macOS el puerto 5000 lo ocupa AirPlay (Control Center): usa 5050, 8000…

5. Protocolos de comunicación (Tema 2.3)

Tipos de protocolos

  • Basados en texto: se envían cadenas de caracteres (representación tipo ASCII).
  • De solicitud-respuesta: un lado invoca una petición y espera una respuesta.

HTTP - características

  • Hyper Text Transfer Protocol (RFC 1945). Basado en la definición de URL. No es lo mismo que HTML.
  • El cliente pide una acción al servidor y éste le envía el resultado.
  • Versiones: HTTP 0.9 (texto sin formato) → 1.0 (formatos MIME) → 1.1 (nuevos servicios, reinicio de comunicaciones).
  • Utilizado por el 100 % de usuarios y servidores.
  • URL = objeto al que se le puede pedir la ejecución de un método y obtener resultados según los parámetros.
  • Protocolo tan genérico que permite definir tus propios comportamientos.
  • Sin estado: no recuerda peticiones de clientes. Primera solución: cookies.
Estado de la comunicación: si guardo información de comunicaciones anteriores, la conexión tiene estado. Si HTTP no tuviera estado, en cada visita tendrías que hacer login de nuevo; con cookies el servidor te envía un identificador aleatorio que tu navegador devuelve para reconocerte. (Importa más en DAD II.)

HTTP - estructura de un mensaje

Un mensaje (petición o respuesta) tiene: primera línea · cabeceras (pares field-name:field-value<CRLF>; metainformación, p. ej. el tamaño del cuerpo) · línea en blanco (CRLF) · cuerpo (entity body).

TipoPrimera líneaEjemplo
Petición (request)Método + recurso (URL) + versión de HTTPGET http://www.w3.org/pub/WWW/TheProject.html HTTP/1.0
Respuesta (response)Versión + código de estado (3 dígitos) + frase descriptivaHTTP/1.0 404 Not Found

Cabeceras: General Header, Request/Response Header y Entity Header. El cuerpo de la petición lleva info extra/parámetros para el método; el de la respuesta, info para el cliente.

HTTP - métodos

MétodoFunciónVersión

El profe: no hay que aprender todos. Los 4 importantes: GET, POST, PUT, DELETE.

FTP - File Transfer Protocol (RFC 959)

  • Permite compartir ficheros (binarios o de datos), facilita el uso de ordenadores remotos, protege al usuario de las variaciones del sistema de ficheros de cada host y transfiere ficheros real y eficientemente. Diseñado para ser usado por programas.
  • Dos conexiones: control (User-PI ↔ Server-PI; comandos y respuestas; puerto 21, well-known port) y datos (User-DTP ↔ Server-DTP; transferencia de ficheros; puerto 20).
  • PI = Protocol Interpreter (intercambia comandos y parámetros). DTP = Data Transfer Process.
AspectoOpciones
Representación (TYPE)ASCII (defecto, texto, A) · EBCDIC (E) · IMAGE (I, binarios, grupos de 8 bits) · LOCAL (byte lógico definido por el emisor)
Control de formato (ASCII/EBCDIC)NON PRINT (defecto) · TELNET FORMAT CONTROLS · CARRIAGE CONTROL (ASA)
Estructura (STRU)File (defecto, bytes sin estructura) · Record · Page
Modo de transmisión (MODE)Stream (flujo de bytes) · Block (bloques con cabecera) · Compressed

ServicioRETR descargar · STOR subir · STOU subir con nombre único · APPE añadir al final · REST reanudar · RNFR/RNTO renombrar · ABOR · DELE borrar fichero · RMD/MKD borrar/crear directorio · PWD · LIST/NLST listar · SITE · SYST · STAT · HELP · NOOP
PORT: IP = h1.h2.h3.h4. Puerto = número de 16 bits con p1 = 8 bits de más peso y p2 = 8 de menos peso → puerto = p1·256 + p2. Ej.: 4096 = 212 → p1 = 16, p2 = 0 → PORT 127,0,0,1,16,0.

Implementación mínima: ASCII Non-print, modo stream, estructura File y Record, comandos user, quit, port, type, mode, stru, retr, stor, noop.

Cada respuesta = código numérico de 3 dígitos + texto descriptivo (no estándar). Multilínea: 123-línea… y la última 123 última línea.

6. Plantillas para el examen de programación

Estructura base (siempre igual)

El examen pide un servidor multihilo con un protocolo de comandos de texto. Se parte siempre de estas tres clases; lo que cambia es el switch de comandos del hilo.

Servidor: ServerSocket + bucle accept() + un hilo por cliente (puerto el que diga el enunciado; si no, uno cualquiera).

import java.io.IOException;
import java.net.ServerSocket;
import java.net.Socket;

public class Servidor {
    public static final int PUERTO = 5050;

    public void ejecutar() {
        try {
            ServerSocket serverSocket = new ServerSocket(Servidor.PUERTO);
            System.out.println("Servidor lanzado esperando clientes...");
            while (true) {
                Socket socket = serverSocket.accept();     // se bloquea hasta que llega un cliente
                HiloServidor hilo = new HiloServidor(socket);
                hilo.start();                              // el main vuelve al accept() enseguida
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    public static void main(String[] args) {
        (new Servidor()).ejecutar();
    }
}

Hilo (aquí está todo lo que cambia): lee línea → split(" ") → switch(partes[0]) → responde y flush().

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.net.Socket;

public class HiloServidor extends Thread {
    private Socket socket;

    public HiloServidor(Socket socket) {
        this.socket = socket;
    }

    @Override
    public void run() {
        try {
            BufferedReader br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
            PrintWriter pw = new PrintWriter(new OutputStreamWriter(socket.getOutputStream()));
            boolean salir = false;
            while (!salir) {
                String linea = br.readLine();
                if (linea == null) break;                  // el cliente cerro la conexion
                String[] partes = linea.split(" ");
                String respuesta = "";
                switch (partes[0].toUpperCase()) {
                case "SUMA":
                    respuesta = "" + (Integer.parseInt(partes[1]) + Integer.parseInt(partes[2]));
                    break;
                case "RESTA":
                    respuesta = "" + (Integer.parseInt(partes[1]) - Integer.parseInt(partes[2]));
                    break;
                case "MULTIPLICA":
                    respuesta = "" + (Integer.parseInt(partes[1]) * Integer.parseInt(partes[2]));
                    break;
                case "EXIT":
                    respuesta = "Adios";
                    salir = true;
                    break;
                default:
                    respuesta = "Comando no reconocido";
                }
                pw.println(respuesta);
                pw.flush();
            }
            socket.close();
        } catch (IOException | NumberFormatException | ArrayIndexOutOfBoundsException e) {
            System.out.println("Conexion finalizada: " + e);
        }
    }
}

Cliente (lectura por teclado; da puntos y se hace rápido; el host debe coincidir con el del servidor; termina al escribir EXIT).

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.net.Socket;
import java.util.Scanner;

public class Cliente {
    public void ejecutar() {
        try (Socket socket = new Socket("127.0.0.1", Servidor.PUERTO)) {
            PrintWriter pw = new PrintWriter(new OutputStreamWriter(socket.getOutputStream()));
            BufferedReader br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
            Scanner teclado = new Scanner(System.in);
            String linea = "";
            System.out.println("Comandos: SUMA a b | RESTA a b | MULTIPLICA a b | EXIT");
            while (!linea.equalsIgnoreCase("EXIT")) {
                linea = teclado.nextLine();
                pw.println(linea);
                pw.flush();
                System.out.println(br.readLine());
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    public static void main(String[] args) {
        (new Cliente()).ejecutar();
    }
}

Truquitos que se repiten

  • partes = linea.split(" ") corta por espacios; partes[0] es el comando.
  • Integer.parseInt(partes[1]): de String a entero (puede lanzar NumberFormatException).
  • Si un parámetro puede llevar espacios (nombre completo, descripción): split(" ", 3) o substring + indexOf.
  • Siempre comprobar el nº de partes (partes.length) y que el elemento exista antes de operar.
  • El estado compartido entre clientes (Hashtable) vive en el Servidor (o en un atributo static) y se pasa a cada hilo: new HiloServidor(socket, this).
  • Hashtable es thread-safe; para operaciones compuestas (comprobar + insertar) usa synchronized.
  • EXIT: sale del bucle, cierra el socket (cerrarSocket()); en la variante con ArrayList de hilos, servidor.matarHilo(id).
  • Siempre pw.flush() tras println, o el cliente se queda esperando (bloqueo indefinido).
