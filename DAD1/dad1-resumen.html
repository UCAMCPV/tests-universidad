1. Computación distribuida (Tema 1.1)

La idea en una frase

Antes, un programa corría en un solo ordenador con una sola CPU (modelo monoprocesador). Hoy muchos programas se reparten entre varios ordenadores conectados por red que se ponen de acuerdo para hacer una tarea. Eso es la computación distribuida.

Sistema distribuido: conjunto de computadores independientes, interconectados a través de una red, capaces de colaborar para realizar una tarea.

¿Qué significa «independientes»? Que no comparten memoria ni espacio de ejecución: cada uno tiene su RAM, su sistema operativo y sus procesos. Por eso, la única forma de que colaboren es mandarse mensajes por la red (eso es la comunicación entre procesos, capítulo 2).

Extra · ejemplos cotidianos: cuando abres WhatsApp, tu móvil (cliente) habla con servidores de WhatsApp; al pagar online, tu navegador, el servidor de la tienda y el del banco colaboran. Ninguno ve la memoria de los otros: solo se mandan mensajes.

  • Finales de los 80: World Wide Web (WWW).

2. Comunicación entre procesos - IPC (Temas 1.2 y 2.1)

La idea en una frase

Si un sistema distribuido es un conjunto de procesos independientes, la comunicación entre procesos (IPC) es lo que los une: un proceso emisor envía datos y otro receptor los recibe. Para entenderse necesitan un protocolo (unas reglas): ¿quién habla primero?, ¿en qué formato?, ¿cómo se avisa de que se ha terminado?

  • Unicast: la comunicación va de un proceso a otro (un cliente con un servidor).
  • Multicast: de un proceso a varios a la vez.
  • El sistema operativo ofrece mecanismos para comunicarse: colas de mensajes, semáforos y regiones de memoria compartida.
  • Normalmente se programa sobre un nivel de abstracción que oculta el SO. En Java, ese nivel son las clases de sockets (capítulo 5).

Operaciones primitivas

Son las acciones básicas de cualquier comunicación. Cada proceso las invoca de forma independiente (el otro no sabe cuándo lo hará) y cada invocación provoca un evento (p. ej. enviar implica que se transmiten datos al receptor).

OperaciónQuién la haceQué significa
EnviarEmisorTransmite datos hacia el receptor.
RecibirReceptorRecoge los datos que llegan.
ConectarAmbosUno invoca solicitar-conexión y el otro aceptar-conexión.
DesconectarAmbosLibera los dos extremos de la comunicación.
Relación con Java: new Socket(..) = solicitar conexión; serverSocket.accept() = aceptar conexión; println() = enviar; readLine() = recibir; close() = desconectar.

Sincronización de eventos: ¿se espera o no?

Los dos extremos son independientes, así que surge la pregunta: ¿cómo sabe uno que el otro ha terminado? (Ejemplo: en HTTP, ¿cómo sabe el servidor que debe enviar los datos?). La forma más sencilla es usar peticiones bloqueantes: la operación no termina hasta que ocurre lo esperado.

TipoTambién se llamaQué hace el programaEjemplo
BloqueanteSíncronaSe queda esperando hasta que la operación terminaLa petición web: el navegador espera la respuesta
No bloqueanteAsíncronaSigue ejecutando sin esperar; se le avisa despuésLa respuesta del servidor llega «cuando llega»
Extra · analogía: síncrono = una llamada de teléfono (hasta que no contestan no hablas con nadie más); asíncrono = una carta (la envías y sigues con tu vida; la respuesta llegará).
Bloqueo indefinido: si lo que esperas nunca llega, una operación bloqueante nunca se desbloquea y el programa se queda colgado para siempre.

Las cuatro combinaciones de enviar y recibir

EnviarRecibirQué ocurre (línea de tiempo)
SíncronoSíncronoEl emisor empieza enviar bloqueante y el receptor recibir bloqueante. Cuando llegan los datos, la librería IPC devuelve un asentimiento transparente al emisor; ambos terminan.
AsíncronoSíncronoEl emisor envía sin bloquearse y sigue. El receptor se bloquea hasta que llegan los datos; entonces su recibir retorna.
SíncronoAsíncronoEscenario 1: el receptor lanza recibir no bloqueante antes y cuando llegan los datos hay asentimiento y todo termina bien.
Escenario 2: el receptor invoca recibir no bloqueante y retorna inmediatamente (aún no hay datos); luego el emisor invoca enviar bloqueante y no hay nadie esperando → bloqueo indefinido.
Escenario 3: el receptor invoca recibir no bloqueante, retorna, y se le notifica la llegada de los datos cuando ocurre.
AsíncronoAsíncronoNadie se bloquea. Al proceso receptor se le notifica la llegada de los datos y estos ya están disponibles.

Cómo se evita el bloqueo indefinido

Dos soluciones, y es pregunta clásica de examen:

  1. Temporizadores (timers): se fija un tiempo máximo de espera para la operación. Si la respuesta no llega a tiempo, el proceso abandona la espera y puede reaccionar, en vez de quedarse colgado.
  2. Proceso hijo o hilo de ejecución: la espera se hace en otro hilo, y el programa principal puede seguir haciendo otras tareas. Es útil para tareas lentas como conexiones de red o grabación en disco.
Extra · en Java: un temporizador sobre un socket se programa con socket.setSoTimeout(5000) (si readLine() espera más de 5 s lanza SocketTimeoutException). La solución con hilos es todo el capítulo 4.

Comunicación con estado y sin estado

El estado de un objeto son los valores que tienen sus atributos en un momento dado (si un atributo vale 5, ese valor define su estado; mientras no cambie, el estado se mantiene).

Aplicado a la comunicación: si el proceso A envía información al proceso B y B guarda información de las comunicaciones anteriores, decimos que la conexión tiene estado. Si B no recuerda nada de peticiones anteriores, es sin estado.

Ejemplo del profesor: ¿qué pasa cuando haces login en una web si HTTP no tiene estado? Que en cada página tendrías que volver a introducir tus datos, porque el servidor «no recuerda quién eres». Solución: las cookies: al iniciar sesión el servidor te envía un identificador (un número aleatorio); tu navegador lo guarda y lo manda en cada petición, y así el servidor te reconoce. (Esto es poco importante en DAD I y más en DAD II.)

4. Hilos de ejecución en Java

Qué es un hilo (con analogía)

Hilo de ejecución: la secuencia única de control de flujo dentro de un programa; la unidad de código más pequeña que se puede ejecutar.

Todo programa Java arranca con un hilo: el hilo main, que ejecuta las instrucciones una detrás de otra. Un hilo adicional es otra «línea de ejecución» que corre a la vez que el main dentro del mismo programa.

Extra · analogía: una cocina. Si cocinas tú solo (un hilo) haces los pasos uno tras otro: cortas, fríes, sirves. Con ayudantes (varios hilos) uno corta mientras otro fríe al mismo tiempo, pero comparten la misma cocina (la memoria del programa), así que deben coordinarse para no pisarse (ver «sincronización»).

  • El main duerme 1,2 s y escribe «Lanzado...». Mientras, el hilo ya está escribiendo.
El hilo secundario arranca con start() y avanza en paralelo al main: el «Lanzado...» sale en medio de las ejecuciones (a 1,2 s), no al final.

Compartir datos: condición de carrera y synchronized

Los hilos de un mismo programa comparten la memoria. Si varios modifican la misma variable a la vez, pueden pisarse. Ejemplo típico: contador++ parece una sola operación pero son tres: leer el valor, sumar 1 y escribir el resultado.

PasoHilo AHilo BValor en memoria
1lee 55
2lee 5 (A aún no ha escrito)5
3calcula 6 y escribe 66
4calcula 6 y escribe 66 (debería ser 7: se perdió un incremento)

A esto se le llama condición de carrera: el resultado depende del orden en que se intercalen los hilos. Por eso 5 hilos sumando 1000 veces no dan 5000 sino un número menor y distinto en cada ejecución.

Solución: synchronized. Un método o bloque synchronized solo puede ser ejecutado por un hilo a la vez sobre el mismo objeto; los demás esperan su turno.

package edu.ucam.hilos.contador;

//Nombre de clase debe ser Camel Sense. No válidos: contador o cONTADOR...
public class Contador {

    private int total = 0;
    
    public synchronized void sumaUno() {
        this.total = this.total + 1;
    }
    
    public int getTotal() {
        return this.total;
    }
}
package edu.ucam.hilos.contador;

public class HiloContador extends Thread {
    
    private Contador contador;
    
    public HiloContador (Contador contador) {
        this.contador = contador;

    public Contador getContador() {
        return contador;
    }

    public void setContador(Contador contador) {
        this.contador = contador;
    }

        }

        }
    }
}

  • Contador guarda total y su método sumaUno() es synchronized: el incremento ya es atómico.
  • Root lanza 200 hilos (200 objetos HiloContador), todos con el mismo Contador.

5. Sockets (Tema 2.2)

Qué es un socket

Socket: punto de conexión entre dos procesos, identificado por una IP y un puerto.
  • IP: la dirección de la máquina en la red (127.0.0.1 o localhost = esta misma máquina, ideal para pruebas).
  • Puerto: un número (0–65535) que identifica qué programa de esa máquina recibe los datos. Un servidor elige su puerto y los clientes lo usan para llegar a él.
  • En la comunicación hay dos sockets, uno en cada extremo; los dos puertos (el del servidor y el del cliente) identifican la comunicación. El del servidor lo elegimos nosotros; el del cliente lo asigna el sistema operativo al azar.
  • Para comunicarte necesitas un objeto de la clase Socket (igual que para tener un hilo necesitas la clase Thread). Y, como siempre, tiene que haber un protocolo.

Cómo se establece una conexión: servidor y cliente

PasoServidorCliente
1Crear socket (socket())Crear socket (socket())
2bind(): asocia el socket a un puerto del sistema operativo (le dice al SO «este proceso ocupa este puerto»). Nosotros especificamos el puerto del servidor.bind(): se le asigna un puerto (aleatorio, lo genera el programa/SO).
3listen(): permite que se puedan conectar a nuestra máquina.
4accept(): acepta la petición entrante (y se queda esperando hasta que llega).Se conecta al servidor (IP + puerto).
5leer() / escribir()escribir() / leer() (el que lee espera a que el otro escriba)

Mientras el servidor está en accept() o readLine(), ese hilo no avanza: está esperando. Por eso un servidor con un solo hilo atiende a un único cliente a la vez.
En Java, new ServerSocket(puerto) hace por ti socket + bind + listen. Pregunta de examen: «¿cómo se activa un socket (servidor)?» → con accept(): el servidor se para esperando y continúa cuando el cliente se conecta.

Un socket te da flujos de bytes: getInputStream() (lo que llega) y getOutputStream() (lo que sale). Para trabajar cómodamente con texto línea a línea se «envuelven» en otras clases, como cajas dentro de cajas:

LEER:    socket.getInputStream()  ->  InputStreamReader  ->  BufferedReader
         (bytes que llegan)          (bytes -> caracteres)  (permite readLine(): una línea entera)

ESCRIBIR: PrintWriter  ->  OutputStreamWriter  ->  socket.getOutputStream()
          (println)        (caracteres -> bytes)    (bytes que salen)
BufferedReader br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
PrintWriter    pw = new PrintWriter(new OutputStreamWriter(socket.getOutputStream()));

String linea = br.readLine();   // BLOQUEA hasta que llega una línea; devuelve null si el otro cerró
pw.println("texto a enviar");   // escribe la línea (con salto de línea al final)
pw.flush();                     // ¡IMPRESCINDIBLE! fuerza el envío; sin flush se queda en el buffer
Tres detalles que cuestan puntos: (1) sin flush() el otro lado se queda esperando para siempre; (2) readLine() devuelve null cuando el otro extremo cierra la conexión; (3) el protocolo es una línea por mensaje: println envía y readLine lee exactamente una línea.
Orden importante en el servidor (apuntes): primero new ServerSocket(PUERTO), después accept() (que devuelve el Socket) y solo entonces crear los buffers sobre ese socket. En el cliente, primero new Socket(host, PUERTO) y luego los buffers.

Ejemplo 2 (echo): lo que escribes en el cliente te lo devuelve el servidor

El cliente lee del teclado con Scanner en un bucle, envía cada línea y muestra la respuesta; el servidor la imprime y la devuelve. Servidor y cliente (apartados esenciales):

// SERVIDOR (echo)
Socket socket = serverSocket.accept();
while (true) {
    PrintWriter pw = new PrintWriter(new OutputStreamWriter(socket.getOutputStream()));
    BufferedReader br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
    String linea = br.readLine();
    System.out.println("Linea recibida en servidor: " + linea);
    pw.println(linea);  pw.flush();                // eco
}

// CLIENTE (echo)

    String linea = teclado.nextLine();
    pw.println(linea);  pw.flush();
    System.out.println(br.readLine());
}
Este servidor atiende a un solo cliente: un segundo cliente conecta pero nadie le responde, porque el servidor sigue dentro de su bucle con el primero. Servidor multihilo: un hilo por cliente

Ejercicio del profesor: «cliente no tocar; servidor hay que bifurcar: objeto Thread (clase) y run; leer y hablar con cliente; si llega un cliente lanza un nuevo hilo».

6. Protocolos de comunicación: HTTP y FTP (Tema 2.3)

Tipos de protocolos

Un protocolo es el conjunto de reglas que acuerdan dos programas para entenderse. Los dos de este tema comparten dos rasgos:

  • Basados en texto: se envían cadenas de caracteres (representación tipo ASCII), legibles por una persona.

FTP: qué es y qué pretende

FTP (File Transfer Protocol, RFC 959): protocolo para transferir ficheros entre ordenadores. Está diseñado para ser usado por programas.
  • Permite compartir ficheros (binarios o de datos).
  • Facilita el uso de ordenadores remotos.
  • Protege al usuario de las variaciones en el sistema de ficheros de los distintos hosts.
  • Transfiere ficheros real y eficientemente.

FTP: el comando PORT y cómo se calcula

PORT h1,h2,h3,h4,p1,p2: la IP es h1.h2.h3.h4. El puerto es un número de 16 bits que se reparte en dos números de 8 bits: p1 = los 8 bits de más peso y p2 = los 8 de menos peso.

Puerto = p1 × 256 + p2 · y al revés: p1 = puerto ÷ 256 (entero), p2 = resto.
PuertoCálculoPORT
40964096 = 212 → p1 = 16, p2 = 0 (16 × 256 + 0)PORT 127,0,0,1,16,0
50005000 ÷ 256 = 19 resto 136 → p1 = 19, p2 = 136PORT 192,168,1,10,19,136
2121 ÷ 256 = 0 resto 21 → p1 = 0, p2 = 21PORT 127,0,0,1,0,21
Extra · activo vs pasivo: en modo activo el cliente manda PORT y es el servidor quien abre la conexión de datos hacia el cliente. En modo pasivo el cliente manda PASV y el servidor queda «en escucha» y responde con 227 Entering Passive Mode … (IP y puerto con el mismo formato) para que el cliente abra la conexión de datos.

7. El servidor multihilo del examen: receta, plantillas y ejemplos resueltos

Qué te piden siempre

El ejercicio de desarrollo (5 puntos) es siempre de la misma familia: «el equipo está desarrollando un sistema al que se conectan clientes mediante Sockets; implementa el hilo de ejecución del servidor que gestiona los comandos recibidos». Te dan una tabla de comandos de texto (ALTAEMPLEADO id nombre, ENTRADA id…) con las respuestas exactas que debe devolver, y reglas de negocio («no se puede fichar entrada si ya hay una abierta»). Tú escribes el hilo (y quizá una clase de datos).

Idea central: un cliente = un hilo = un socket. El hilo lee una línea, la interpreta (split + switch), ejecuta la regla de negocio y escribe una línea de respuesta. Se repite hasta que el cliente se va.

Receta de 7 pasos

  1. Atributos y constructor: private Socket socket; (y private Servidor servidor; si hay estado compartido) + constructor que los recibe. La clase extends Thread.
  2. run() con try { … } catch (IOException e): aquí van los buffers: BufferedReader br sobre socket.getInputStream() y PrintWriter pw sobre socket.getOutputStream().
  3. Bucle de lectura: while ((linea = br.readLine()) != null) (o while(!salir) si hay comando EXIT).
  4. Trocear la línea: String[] partes = linea.split(" "); → partes[0] es el comando. Si algún campo lleva espacios (nombre completo, descripción), usa split(" ", 3) o substring+indexOf.
  5. switch (partes[0]) con un case por comando y un default («Comando no reconocido»).
  6. En cada caso: comprobar partes.length, que el objeto exista (empleado, matrícula…) y las reglas del enunciado; construir la respuesta con el texto exacto que pide el enunciado.
  7. Responder: pw.println(respuesta); pw.flush();. Al terminar (EXIT o null), cerrar el socket.

Solo hace accept() en bucle y lanza un hilo por cliente. Puerto: el que diga el enunciado; si no dice nada, pon uno (8000, 5050…).

Plantilla 2 · Hilo con switch (aquí está todo lo que cambia)

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.net.Socket;

public class HiloServidor extends Thread {
    private Socket socket;

    public HiloServidor(Socket socket) {
        this.socket = socket;
    }

    @Override
    public void run() {
        try {
            BufferedReader br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
            PrintWriter pw = new PrintWriter(new OutputStreamWriter(socket.getOutputStream()));
            boolean salir = false;
            while (!salir) {
                String linea = br.readLine();
                if (linea == null) break;                  // el cliente cerro la conexion
                String[] partes = linea.split(" ");
                String respuesta = "";
                switch (partes[0].toUpperCase()) {
                case "SUMA":
                    respuesta = "" + (Integer.parseInt(partes[1]) + Integer.parseInt(partes[2]));
                    break;
                case "RESTA":
                    respuesta = "" + (Integer.parseInt(partes[1]) - Integer.parseInt(partes[2]));
                    break;
                case "MULTIPLICA":
                    respuesta = "" + (Integer.parseInt(partes[1]) * Integer.parseInt(partes[2]));
                    break;
                case "EXIT":
                    respuesta = "Adios";
                    salir = true;
                    break;
                default:
                    respuesta = "Comando no reconocido";
                }
                pw.println(respuesta);
                pw.flush();
            }
            socket.close();
        } catch (IOException | NumberFormatException | ArrayIndexOutOfBoundsException e) {
            System.out.println("Conexion finalizada: " + e);
        }
    }
}

Qué hace cada trozo:

  • public class HiloServidor extends Thread + atributo socket + constructor: guarda el socket de su cliente.
  • BufferedReader br …; PrintWriter pw …: los canales de lectura y escritura con ese cliente.
  • boolean salir = false; y while (!salir): el bucle sigue mientras no se escriba EXIT.
  • String linea = br.readLine(); if (linea == null) break;: lee una línea; si es null el cliente se desconectó y salimos para no quedarnos en bucle infinito.
  • String[] partes = linea.split(" ") y switch (partes[0].toUpperCase()): elige el comando sin distinguir mayúsculas.
  • Integer.parseInt(partes[1]): convierte el texto «2» en el número 2. Si no es un número lanza NumberFormatException (por eso va dentro del try/catch).
  • respuesta se rellena en cada case; al final una sola vez pw.println(respuesta); pw.flush();.
  • socket.close() al salir del bucle libera la conexión.

Ejemplo resuelto 2 · Multas con Hashtable (examen de otros años)

Gestiona multas por matrícula. Aquí aparece lo nuevo: los hilos deben compartir los datos de todos los clientes. Se hace guardando una Hashtable<String, Matricula> en el Servidor y pasando el servidor a cada hilo.

  1. Matricula (clase de datos): ArrayList<Integer> con las multas; getCuantiaMultas() suma todas (como sumar la cesta en POO); addMulta(Integer); addPago(int); getPendiente() = multas − pagado.
  2. Servidor: atributo Hashtable y métodos getMatricula, addMatricula, removeMatricula para que los hilos accedan. En accept() se hace new HiloServidor(socket, this) (this = el servidor).
  3. HiloServidor: guarda servidor y socket; boolean salir; actualiza matricula = servidor.getMatricula(partes[1]) en cada comando; el switch aplica ALTA / MULTA / PAGO / PENDIENTE / BORRAR; «if (partes.length == 3 && matricula != null)» para exigir 3 datos y que exista.
import java.util.ArrayList;

public class Matricula {
    private String numero;
    private ArrayList<Integer> multas = new ArrayList<Integer>();
    private int pagado = 0;

    public Matricula(String numero) {
        this.numero = numero;
    }
    public String getNumero() { return numero; }

    public void addMulta(Integer cuantia) { multas.add(cuantia); }

    public int getCuantiaMultas() {            // suma de todas las multas
        int total = 0;
        for (Integer m : multas) total += m;
        return total;
    }
    public void addPago(int cantidad) { pagado += cantidad; }

    public int getPendiente() { return getCuantiaMultas() - pagado; }
}

Ejemplo resuelto 3 · Materiales (y matar hilos con EXIT)

Igual que multas, pero además el Servidor guarda los hilos en un ArrayList<HiloServidor> con un id numérico para poder cerrarlos. Con EXIT, el hilo llama a servidor.matarHilo(id), que busca el hilo por id, llama a su cerrarSocket() y lo quita de la lista. La descripción puede tener espacios, por eso se usa substring + indexOf: se queda con todo lo que va tras la cantidad.

public class Material {
    private String id;
    private String descripcion;
    private int cantidad;

    public Material(String id, String descripcion, int cantidad) {
        this.id = id;
        this.descripcion = descripcion;
        this.cantidad = cantidad;
    }
    public String getId() { return id; }
    public int getCantidad() { return cantidad; }

    public boolean addReserva(int unidades) {      // resta unidades si hay stock
        if (unidades <= 0 || unidades > cantidad) return false;
        cantidad -= unidades;
        return true;
    }

    @Override
    public String toString() {
        return id + " - " + descripcion + " (" + cantidad + " uds)";
    }
}
import java.io.IOException;
import java.net.ServerSocket;
import java.net.Socket;
import java.util.ArrayList;
import java.util.Hashtable;

public class Servidor {
    public static final int PUERTO = 5050;
    private Hashtable<String, Material> materiales = new Hashtable<String, Material>();
    private ArrayList<HiloServidor> hilos = new ArrayList<HiloServidor>();   // para poder "matar" hilos
    private int contadorHilos = 0;

    public synchronized String addMaterial(String id, String descripcion, int cantidad) {
        if (materiales.containsKey(id)) return "Error. El material ya existe";
        materiales.put(id, new Material(id, descripcion, cantidad));
        return "Ok. Material insertado";
    }
    public Material getMaterial(String id) { return materiales.get(id); }

    public synchronized String listar() {
        StringBuilder sb = new StringBuilder();
        for (Material m : materiales.values()) sb.append(m).append(" | ");
        return sb.length() == 0 ? "No hay materiales" : sb.toString();
    }

    public synchronized void matarHilo(int idHilo) {
        for (HiloServidor h : hilos) {
            if (h.getIdHilo() == idHilo) {
                h.cerrarSocket();
                hilos.remove(h);
                break;
            }
        }
    }

    public void ejecutar() {
        try (ServerSocket serverSocket = new ServerSocket(PUERTO)) {
            while (true) {
                Socket socket = serverSocket.accept();
                HiloServidor hilo = new HiloServidor(socket, this, contadorHilos++);
                synchronized (this) { hilos.add(hilo); }
                hilo.start();
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    public static void main(String[] args) {
        (new Servidor()).ejecutar();
    }
}
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.net.Socket;

public class HiloServidor extends Thread {

    private Servidor servidor;
    private int idHilo;
    private boolean salir = false;

    public HiloServidor(Socket socket, Servidor servidor, int idHilo) {
        this.socket = socket;
        this.servidor = servidor;
        this.idHilo = idHilo;
    }
    public int getIdHilo() { return idHilo; }

    public void cerrarSocket() {
        try { socket.close(); } catch (IOException e) { }
    }

    @Override
    public void run() {
        try {
            BufferedReader br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
            PrintWriter pw = new PrintWriter(new OutputStreamWriter(socket.getOutputStream()));
            while (!salir) {
                String lineaLeida = br.readLine();
                if (lineaLeida == null) break;
                String[] partes = lineaLeida.split(" ");
                String respuesta = "";
                switch (partes[0].toUpperCase()) {
                case "ALTA": {   // ALTA id cantidad descripcion con espacios...
                    if (partes.length < 4) { respuesta = "Error. Uso: ALTA id cantidad descripcion"; break; }
                    // substring + indexOf: coge todo lo que hay tras el 3er espacio
                    int inicio = lineaLeida.indexOf(partes[2]) + partes[2].length() + 1;
                    String descripcion = lineaLeida.substring(inicio);
                    respuesta = servidor.addMaterial(partes[1], descripcion, Integer.parseInt(partes[2]));
                    break;
                }
                case "RESERVA": {
                    Material m = partes.length == 3 ? servidor.getMaterial(partes[1]) : null;
                    if (m == null) respuesta = "Error. Uso: RESERVA id unidades (el material debe existir)";
                    else respuesta = m.addReserva(Integer.parseInt(partes[2])) ? "Ok. Reserva realizada" : "Error. Stock insuficiente";
                    break;
                }
                case "LISTAR":
                    respuesta = servidor.listar();
                    break;
                case "EXIT":
                    respuesta = "Adios";
                    salir = true;
                    break;
                default:
                    respuesta = "Comando no reconocido";
                }
                pw.println(respuesta);
                pw.flush();
            }
            servidor.matarHilo(this.idHilo);    // EXIT: el servidor cierra el socket y borra el hilo
        } catch (IOException | NumberFormatException e) {
            System.out.println("Conexion finalizada: " + e);
        }
    }
}
Congresos (tercer ejercicio de otros años) es lo mismo con una clase Congreso y un comando LISTAR: el servidor devuelve (una copia de) la Hashtable y el hilo recorre los valores concatenando sus toString(); BORRAR id llama a servidor.removeCongreso(id).

Ejemplo resuelto 4 · El parcial real: fichaje de empleados

Comandos: ALTAEMPLEADO id nombreCompleto, ENTRADA id, SALIDA id, HORAS id, ESTADO id. Reglas: no se puede ENTRADA si ya hay entrada abierta; no se puede SALIDA si no la hay. Existe una clase GestionFechas con getHoraActual() (Timestamp), getHorasEntre(inicio, fin) (float) y getTexto(Timestamp) (String).

Cómo pensarlo: cada empleado tiene un estado (¿entrada abierta? ¿desde cuándo?) y unas horas acumuladas. ENTRADA guarda la hora actual; SALIDA suma getHorasEntre(entrada, ahora) y borra la entrada abierta; ESTADO consulta; HORAS devuelve el acumulado.

Clase de datos Empleado:

import java.sql.Timestamp;

public class Empleado {
    private String id;
    private String nombre;
    private Timestamp entrada;      // null si no hay entrada abierta
    private float horasAcumuladas = 0;

    public Empleado(String id, String nombre) {
        this.id = id;
        this.nombre = nombre;
    }
    public String getId() { return id; }
    public String getNombre() { return nombre; }
    public Timestamp getEntrada() { return entrada; }
    public void setEntrada(Timestamp entrada) { this.entrada = entrada; }
    public boolean tieneEntradaAbierta() { return entrada != null; }
    public float getHorasAcumuladas() { return horasAcumuladas; }
    public void sumaHoras(float horas) { this.horasAcumuladas += horas; }
}

Clase pedida: HiloGestionFichaje (una excepción por comando y mensajes idénticos al enunciado):

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.net.Socket;
import java.sql.Timestamp;
import java.util.Hashtable;

public class HiloGestionFichaje extends Thread {
    // Listado de empleados (compartido por todos los hilos -> accesos synchronized)
    private static Hashtable<String, Empleado> empleados = new Hashtable<String, Empleado>();

    private Socket socket;
    private BufferedReader br;
    private PrintWriter pw;

    public HiloGestionFichaje(Socket socket) {
        this.socket = socket;
    }

    @Override
    public void run() {
        try {
            // Buffers de comunicacion con el cliente
            this.br = new BufferedReader(new InputStreamReader(this.socket.getInputStream()));
            this.pw = new PrintWriter(new OutputStreamWriter(this.socket.getOutputStream()));

            String linea;
            while ((linea = this.br.readLine()) != null) {
                String respuesta = this.procesar(linea);
                this.pw.println(respuesta);
                this.pw.flush();
            }
        } catch (IOException e) {
            System.out.println("Conexion finalizada");
        } finally {
            try { this.socket.close(); } catch (IOException e) { }
        }
    }

    private String procesar(String linea) {
        String[] partes = linea.trim().split(" ", 3);   // 3: el nombre completo puede llevar espacios
        String comando = partes[0].toUpperCase();

        switch (comando) {
        case "ALTAEMPLEADO":
            if (partes.length < 3) return "Error. Uso: ALTAEMPLEADO idEmpleado nombreCompleto";
            return this.altaEmpleado(partes[1], partes[2]);
        case "ENTRADA":
            if (partes.length < 2) return "Error. Uso: ENTRADA idEmpleado";
            return this.entrada(partes[1]);
        case "SALIDA":
            if (partes.length < 2) return "Error. Uso: SALIDA idEmpleado";
            return this.salida(partes[1]);
        case "HORAS":
            if (partes.length < 2) return "Error. Uso: HORAS idEmpleado";
            return this.horas(partes[1]);
        case "ESTADO":
            if (partes.length < 2) return "Error. Uso: ESTADO idEmpleado";
            return this.estado(partes[1]);
        default:
            return "Error. Comando no reconocido";
        }
    }

    private synchronized String altaEmpleado(String id, String nombre) {
        if (empleados.containsKey(id)) {
            return "Error. El empleado ya existe";
        }
        empleados.put(id, new Empleado(id, nombre));
        return "Ok. Empleado insertado";
    }

    private synchronized String entrada(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        if (e.tieneEntradaAbierta()) {
            return "Error. El empleado ya ha registrado la entrada";
        }
        Timestamp ahora = GestionFechas.getHoraActual();
        e.setEntrada(ahora);
        return "Ok. Entrada registrada. " + GestionFechas.getTexto(ahora);
    }

    private synchronized String salida(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        if (!e.tieneEntradaAbierta()) {
            return "Error. El empleado no tiene registrada entrada";
        }
        Timestamp ahora = GestionFechas.getHoraActual();
        e.sumaHoras(GestionFechas.getHorasEntre(e.getEntrada(), ahora));
        e.setEntrada(null);                              // cierra la entrada abierta
        return "Ok. Salida registrada. " + GestionFechas.getTexto(ahora);
    }

    private synchronized String horas(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        return "Ok. " + e.getNombre() + " tiene trabajadas " + e.getHorasAcumuladas() + " horas.";
    }

    private synchronized String estado(String id) {
        Empleado e = empleados.get(id);
        if (e == null) return "Error. El empleado no existe";
        if (e.tieneEntradaAbierta()) {
            return "El empleado ha registrado entrada: " + GestionFechas.getTexto(e.getEntrada());
        }
        return "El empleado no ha registrado entrada";
    }
}
Qué mira el corrector: buffers bien creados + flush · bucle de lectura · split y switch · alta rechaza duplicados · ENTRADA y SALIDA respetan sus reglas · uso correcto de GestionFechas · mensajes exactos · comprobar si el empleado existe.
El listado de empleados es static y los métodos son synchronized porque lo comparten todos los hilos (todos los clientes). Si el enunciado dice «el listado se podrá almacenar como atributo en la clase implementada», static es la forma de que lo vean todos.

Reglas de oro para los comandos de texto

  • Siempre comprueba partes.length antes de usar partes[1]/partes[2] (si no, ArrayIndexOutOfBoundsException).
  • Siempre comprueba que el objeto existe (empleado, matrícula, libro…) antes de operar con él.
  • Siempre un default en el switch.
  • Los mensajes de respuesta deben ser exactamente los del enunciado (mayúsculas, puntos, tildes).
  • Todo lo compartido entre clientes (la tabla de datos) va en el Servidor o en un atributo static; las operaciones «comprobar y luego insertar» en métodos synchronized.
  • pw.flush() después de cada println.
  • Cierra el socket al terminar (EXIT, null o excepción).

Ejemplo extra · Chat multihilo (eco con varios clientes)

El eco devuelve el mensaje al mismo cliente. Un chat lo reenvía a todos los demás, así que el servidor necesita una lista compartida de clientes. Sigue siendo «un cliente = un hilo = un socket».

Servidor

import java.io.*;
import java.net.*;
import java.util.*;
import java.util.concurrent.CopyOnWriteArrayList;

public class ServidorChat {
    // Lista compartida entre hilos, segura para recorrer mientras otros se conectan o desconectan
    static final List<ManejadorCliente> clientes = new CopyOnWriteArrayList<>();

    public static void main(String[] args) throws IOException {
        ServerSocket servidor = new ServerSocket(5000);
        System.out.println("Chat escuchando en el puerto 5000");
        while (true) {
            Socket socket = servidor.accept();          // bloquea hasta que llega un cliente
            ManejadorCliente m = new ManejadorCliente(socket);
            clientes.add(m);
            new Thread(m).start();                      // un hilo por cliente
        }
    }

    static void difundir(String msg, ManejadorCliente origen) {
        for (ManejadorCliente c : clientes) {
            if (c != origen) c.enviar(msg);
        }
    }
}

class ManejadorCliente implements Runnable {
    private final Socket socket;
    private PrintWriter out;
    private String nombre;

    ManejadorCliente(Socket socket) { this.socket = socket; }

    synchronized void enviar(String msg) { out.println(msg); }

    public void run() {
        try (BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()))) {
            out = new PrintWriter(socket.getOutputStream(), true);
            out.println("Tu nombre:");
            nombre = in.readLine();
            ServidorChat.difundir(">> " + nombre + " se ha unido", this);

            String linea;
            while ((linea = in.readLine()) != null) {
                ServidorChat.difundir(nombre + ": " + linea, this);
            }
        } catch (IOException e) {
            // el cliente se ha caído
        } finally {
            ServidorChat.clientes.remove(this);
            ServidorChat.difundir("<< " + nombre + " se ha ido", this);
            try { socket.close(); } catch (IOException ignored) {}
        }
    }
}

Cliente

import java.io.*;
import java.net.*;

public class ClienteChat {
    public static void main(String[] args) throws IOException {
        Socket socket = new Socket("localhost", 5000);
        BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()));
        PrintWriter out = new PrintWriter(socket.getOutputStream(), true);

        // Hilo que escucha al servidor
        new Thread(() -> {
            try {
                String l;
                while ((l = in.readLine()) != null) System.out.println(l);
            } catch (IOException ignored) {}
        }).start();

        // Hilo principal: teclado -> servidor
        BufferedReader teclado = new BufferedReader(new InputStreamReader(System.in));
        String l;
        while ((l = teclado.readLine()) != null) out.println(l);
    }
}
Por qué 2 hilos en el cliente: readLine() del teclado bloquea; con un solo hilo no podrías recibir mensajes mientras escribes. Por qué CopyOnWriteArrayList: se recorre mientras otros clientes entran o salen (con ArrayList daría ConcurrentModificationException). enviar es synchronized para que dos hilos no mezclen mensajes en el mismo socket. 10. Preguntas de teoría con respuesta modelo

Para repasar el día antes

Cubre la respuesta, contesta en voz alta y compara. Están escritas como se contestarían en el examen.

1. ¿Qué es un hilo y para qué se suele utilizar?

Un hilo de ejecución es la secuencia única de control de flujo dentro de un programa; es la unidad de código más pequeña que se puede ejecutar. Se utiliza para ejecutar tareas lentas, no paralizar el programa principal mientras se hacen otras tareas, evitar bloqueos inaceptables o indefinidos y manejar varias tareas a la vez (por ejemplo, un servidor que atiende a varios clientes).

2. Ventajas de la computación distribuida.

Es económica (los computadores y el acceso a red son baratos), permite compartir recursos, es escalable (se añaden máquinas según crece la carga) y tolera fallos (si un nodo cae, otros siguen). Como inconvenientes: múltiples puntos de fallo y aspectos de seguridad.

3. Características de HTTP y estructura de un paquete.

HTTP (RFC 1945) es un protocolo de texto de solicitud-respuesta basado en URL, usado por el 100 % de usuarios y servidores, genérico, que no es lo mismo que HTML y que no tiene estado (se resuelve con cookies). Un mensaje tiene primera línea (método + recurso + versión en la petición; versión + código + frase en la respuesta), cabeceras campo:valor, una línea en blanco CRLF y el cuerpo.

4. ¿Qué es un socket y cómo se activa?

Es el punto de conexión entre dos procesos, identificado por una IP y un puerto. En el servidor se activa con accept(), que espera hasta que un cliente se conecta.

5. ¿Cómo se crea y lanza un hilo en Java?

Heredando de Thread (class X extends Thread, implementar run() y llamar a start()) o implementando Runnable (implementar run() y lanzar con new Thread(obj).start()).

6. ¿Qué es un bloqueo indefinido y cómo se evita?

Ocurre cuando una petición espera una operación que nunca termina y no se desbloquea. Se evita con temporizadores (límite de espera) o con procesos hijo/hilos de ejecución que hacen la tarea lenta sin paralizar el programa.

7. ¿Por qué el contador no llega a 5000 con 5 hilos que suman 1000?

Porque los 5 hilos comparten el mismo objeto y contador++ no es atómico (leer, sumar, escribir): se pierden incrementos (condición de carrera). Se arregla con synchronized (o AtomicInteger).

8. ¿Por qué salta IllegalThreadStateException?

Porque se llama a start() más de una vez sobre el mismo objeto Thread; un hilo solo se puede arrancar una vez. Hay que crear un objeto nuevo por cada hilo.

9. ¿Por qué salta BindException: Address already in use?

Porque el puerto ya está ocupado, normalmente por una ejecución anterior del servidor que sigue viva (un while(true) que nunca termina y no cierra el ServerSocket).

10. ¿Qué es FTP y cuántas conexiones usa?

File Transfer Protocol (RFC 959) permite transferir ficheros entre ordenadores. Usa dos conexiones: control (comandos y respuestas, puerto 21) y datos (transferencia de ficheros, puerto 20).

11. Explica PORT 192,168,1,10,19,136.

Indica al servidor que abra la conexión de datos a la IP 192.168.1.10 y al puerto 19·256 + 136 = 5000.

12. ¿Qué significan los códigos FTP 2yz, 3yz y 5yz?

2yz: comando ejecutado correctamente (200 Command okay); 3yz: respuesta intermedia positiva que necesita más información (331 User name okay, need password); 5yz: respuesta negativa definitiva (550 Access denied).
