1. Primeros comandos y forma de las órdenes

Objetivo y primeros pasos

El boletín es una primera aproximación a la virtualización por contenedores con Docker, sobre la máquina virtual UbuntuDocker de las prácticas.

docker version   # versión del CLIENTE y del SERVIDOR (daemon) de Docker
docker info      # detalles de la configuración: nº de contenedores e imágenes, drivers…
docker           # sin argumentos: lista de comandos disponibles
El comando docker es el cliente; el trabajo lo hace el servidor (daemon). Por eso docker version muestra dos bloques, Client y Server. (docker --version, con guiones, solo imprime una línea con la versión del cliente.)

La forma docker <objeto> <acción>

El boletín usa la sintaxis por objetos: primero sobre qué se actúa y después qué se hace.

docker  container  run     [opciones]  imagen  [comando]
docker  container  ls | stop | logs | top | stats | rm | start
docker  image      ls | pull | history | inspect | build
docker  volume     ls | inspect | prune            (práctica P2-2)
Docker también admite las formas cortas clásicas (docker run, docker ps, docker images, docker pull). Hacen lo mismo; la forma por objetos es más explícita.

2. Ciclo de vida de un contenedor (pasos 4-16)

Arrancar, listar, parar, inspeccionar y borrar

docker container run --publish 80:80 --detach nginx   # 1.er contenedor: servidor web nginx
docker container ls                                    # contenedores EN EJECUCIÓN
docker container stop <id_del_contenedor>              # lo para (pero sigue existiendo)
docker container ls                                    # ya no aparece…
docker container ls -a                                 # …con -a sí: todos los creados
docker container run --publish 80:80 --detach --name webhost nginx
docker container logs webhost                          # log del servidor en segundo plano
docker container top webhost                           # procesos dentro del contenedor
docker container stats                                 # uso de recursos en vivo (Ctrl+C sale)
docker container rm <id1> <id2> …                     # borra (IDs separados por espacios)
docker container rm -f <id>                            # fuerza el borrado de uno en marcha
OpciónForma largaQué hace
-p 80:80--publishPublica un puerto con el formato host:contenedor: lo que llega al 80 del host va al 80 del contenedor
-d--detachEjecuta el contenedor en segundo plano y devuelve el control de la terminal (imprime el ID)
--name webhost—Da un nombre al contenedor; si no, Docker genera uno aleatorio
-a (en ls)--allLista todos los contenedores, también los detenidos
-f (en rm)--forceBorra el contenedor aunque esté en ejecución

Con el nginx publicado en el puerto 80 puedes abrir http://localhost en la máquina virtual y ver su página de bienvenida.

Respuestas a las preguntas del boletín

  • Paso 7 (tras stop, ls no muestra nada): ls sin opciones solo lista los contenedores en ejecución; el parado sigue existiendo y aparece con ls -a como Exited.
  • Paso 10 («¿Cuántos contenedores veremos con docker container ls -a?»): dos. El primer nginx (detenido, con nombre aleatorio) y webhost (en marcha). Además, el primero tenía que estar parado: dos contenedores no pueden publicar a la vez el mismo puerto 80 del host.
  • Paso 15: rm no deja borrar el contenedor que está en marcha; hay que pararlo antes o usar rm -f.
  • Paso 16: tras borrarlos, docker container ls -a ya no muestra ninguno.
stop ≠ rm. Parar conserva el contenedor y sus cambios; borrar lo elimina. logs = salida del contenedor, top = sus procesos, stats = consumo de CPU, memoria, red y disco en vivo.

3. Entrar en un contenedor (pasos 17-22)

Una shell dentro del contenedor

docker container run -it --name proxy nginx bash   # bash EN LUGAR de nginx; exit lo detiene
docker container run -it --name ubuntu ubuntu       # la imagen ubuntu arranca bash por defecto
apt-get update                                      # (dentro) actualiza la lista de paquetes
apt-get install curl -y                             # (dentro) instala curl sin preguntar
exit                                                # sale y DETIENE el contenedor
docker container start -ai ubuntu                   # vuelve a arrancarlo y se engancha a él
OpciónSignificado
-i (--interactive)Mantiene abierta la entrada estándar: puedes escribir órdenes
-t (--tty)Asigna una terminal (pseudo-TTY). Juntas, -it dan una shell interactiva
start -a (--attach)Conecta la salida del contenedor a tu terminal
start -i (--interactive)Conecta tu teclado a su entrada
apt-get … -yResponde «sí» automáticamente a la confirmación

Qué pasa en cada paso

  • Lo que se escribe después del nombre de la imagen (bash) sustituye al comando por defecto de esa imagen: en el contenedor proxy se abre bash y el servidor nginx no llega a arrancar.
  • bash es entonces el proceso principal: al hacer exit, el proceso termina y el contenedor se detiene (no se borra).
  • La imagen ubuntu tiene bash como comando por defecto, por eso no hace falta escribirlo.
  • docker container start -ai ubuntu arranca el mismo contenedor: curl sigue instalado, porque los cambios viven en la capa de escritura del contenedor mientras este exista. docker container run -it --name ubuntu ubuntu intentaría crear uno nuevo, limpio, y además fallaría porque el nombre ubuntu ya está ocupado.
-t no significa lo mismo en todos los comandos: en run es terminal (TTY); en docker image build -t es la etiqueta (tag) de la imagen.

4. Imágenes y capas (pasos 23-27)

Comandos de imágenes

docker image ls                         # imágenes del sistema (REPOSITORY, TAG, IMAGE ID…)
docker image pull nginx:1.11.9          # otra versión de nginx → nombre:etiqueta
docker image history nginx:latest       # capas de la imagen y la instrucción que creó cada una
docker image inspect nginx:latest       # metadatos en JSON (capas, puertos, comando, entorno…)
docker image pull mysql/mysql-server    # imagen NO oficial → usuario/repositorio
  • Etiqueta (tag): lo que va tras los dos puntos, normalmente la versión. Si no se indica, se usa latest. nginx:1.11.9 y nginx:latest son imágenes distintas del mismo repositorio.
  • Capas: una imagen es una pila de capas de solo lectura. history las enumera; inspect da todos los metadatos.
  • Oficiales y no oficiales: las oficiales tienen solo nombre (nginx, mysql, ubuntu); las de usuarios u organizaciones llevan prefijo. Por eso, tras el paso 26, docker image ls muestra el repositorio como usuario/repositorio (mysql/mysql-server).
Imagen = plantilla de solo lectura (capas). Contenedor = imagen + una capa de escritura propia en ejecución. De una imagen salen tantos contenedores como quieras.

5. Dockerfile: construir «sleepylinux» (pasos 28-34)

Pasos

cd /home/docker/EjemplosDocker/dockerfile-sample-4
# abrir el Dockerfile (Sublime Text) y cambiar el valor de CMD de 10000 a 10
docker image build -t sleepylinux .   # construye la imagen; -t = nombre, . = carpeta actual
docker image ls                       # aparece la nueva imagen sleepylinux
docker container run sleepylinux      # duerme 10 s y termina
docker container run sleepylinux 5    # el 5 sustituye al CMD → duerme 5 s
  • docker image build crea una imagen a partir de un Dockerfile (fichero de texto con las instrucciones).
  • -t sleepylinux (--tag) le pone nombre (y etiqueta, latest si no se indica).
  • El punto final es el contexto de construcción: la carpeta actual, donde está el Dockerfile y los ficheros que pueda copiar.

Paso 34: ¿qué pasa con docker container run sleepylinux 5?

CMD define lo que se ejecuta por defecto y se sustituye por los argumentos escritos tras el nombre de la imagen. Como el CMD de este Dockerfile solo contiene un número (10000, luego 10), ese número es el argumento de sleep, que queda fijado como punto de entrada (ENTRYPOINT). Un Dockerfile con ese comportamiento sería:

FROM ubuntu              # imagen base (la del ejemplo puede ser otra)
ENTRYPOINT ["sleep"]     # comando fijo
CMD ["10"]               # argumento por defecto (antes 10000)

Así, run sleepylinux ejecuta sleep 10 y run sleepylinux 5 ejecuta sleep 5: el contenedor termina a los 5 segundos en lugar de a los 10.

Si el CMD fuera la orden completa (CMD ["sleep", "10"], sin ENTRYPOINT), el 5 sustituiría a toda la orden y Docker intentaría ejecutar un programa llamado «5», con error. Que CMD solo guarde el número indica que sleep va en el ENTRYPOINT.

6. Ejercicios: propuesta de solución

Un comando por paso (propuesta)

El boletín pide resolver cada paso con un único comando. La imagen del servidor de correo poste.io en Docker Hub es analogic/poste.io. Sustituye fernando-terroso por tu nombre y apellidos.

1. docker image pull analogic/poste.io                  # última imagen (etiqueta latest)
2. docker image history analogic/poste.io               # sus capas
3. docker container run -d --name correo-fernando-terroso analogic/poste.io
4. docker container ls                                  # aparece en ejecución
5. docker container stop correo-fernando-terroso
6. docker container ls                                  # ya no aparece
7. docker container ls -a                               # todos, en marcha o no
8. docker container run -d analogic/poste.io:2.2.24     # run descarga la versión si no está
  • Paso 9: guardar los comandos en tarea-Docker-1-nombre-apellidos.txt en el escritorio.
  • No borres los contenedores: al listar todos (docker container ls -a) deben aparecer los creados.
  • En el paso 8, -d no lo exige el enunciado, pero mantiene el contenedor en segundo plano como en el paso 3.

Ideas clave para el examen

  • ls = en marcha; ls -a = todos. Un contenedor parado sigue existiendo hasta rm.
  • -p host:contenedor, -d segundo plano, --name nombre, -it shell interactiva, rm -f forzar, start -ai volver a entrar.
  • Lo escrito tras la imagen sustituye a su comando por defecto (CMD).
  • Etiqueta = versión (:1.11.9, por defecto latest); usuario/repositorio = imagen no oficial.
  • build -t nombre .: -t pone el nombre y el punto es la carpeta del Dockerfile.
