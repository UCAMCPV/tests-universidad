1. El problema: los datos del contenedor son efímeros

Por qué hace falta gestionar el almacenamiento

Un contenedor es la imagen (capas de solo lectura) más una capa de escritura propia. Lo que la aplicación escribe ahí sobrevive a parar y arrancar el contenedor, pero desaparece al borrarlo. Para que los datos (por ejemplo, una base de datos) no dependan del contenedor, se guardan fuera, en el host. La práctica ve las dos formas:

Qué esAlmacenamiento que crea y gestiona Docker en su propia zona del hostUna carpeta concreta del host, elegida por ti, montada en el contenedor
Sintaxis-v nombre:/ruta/en/contenedor (o sin -v, anónimo)-v /ruta/del/host:/ruta/en/contenedor

Los volúmenes sobreviven al contenedor: parar o borrar el contenedor no los borra. Hay que eliminarlos expresamente (docker volume rm o docker volume prune).

2. Volúmenes (pasos 1-12)

Comandos

docker volume prune                          # 1: borra volúmenes sin usar heredados
docker pull mysql                            # 2: imagen oficial de MySQL (= docker image pull)
docker image inspect mysql                   # 3: tiene un apartado "Volumes"
docker container run -d --name mysql -e MYSQL_ALLOW_EMPTY_PASSWORD=True mysql   # 4
docker container ls                          # 5: está en marcha
docker container inspect mysql               # 6: apartados "Volumes" y "Mounts"
docker volume ls                             # 7: aparece un volumen
docker volume inspect <nombre_del_volumen>   # 8: detalle del volumen
OpciónQué hace
-dSegundo plano
--name mysqlNombre del contenedor
-e VAR=valor (--env)Define una variable de entorno dentro del contenedor. MYSQL_ALLOW_EMPTY_PASSWORD=True deja arrancar MySQL con el usuario root sin contraseña (válido solo para pruebas)

Qué se observa

  • Paso 3: la imagen de MySQL declara un volumen para sus datos (/var/lib/mysql); por eso docker image inspect tiene el apartado Volumes. Cada contenedor que se cree sin indicar otra cosa recibe un volumen anónimo para esa ruta.
  • Paso 6: en Mounts, el parámetro Source es la ruta dentro del host donde se está almacenando el volumen; Destination es la ruta dentro del contenedor (/var/lib/mysql).
  • Paso 7: docker volume ls muestra el volumen con un nombre aleatorio largo (64 caracteres hexadecimales).
El boletín inspecciona el volumen con «sus primeros tres dígitos». A diferencia de contenedores e imágenes, Docker busca los volúmenes por su nombre completo: si responde «No such volume», copia el nombre entero de docker volume ls.

Respuestas a las preguntas del boletín

  • Paso 9 (repetir con mysql2): hay dos volúmenes distintos, uno anónimo por contenedor. ¿Cómo distinguir cuál es de cuál? docker volume ls solo muestra el driver y el nombre aleatorio; hay que mirar docker container inspect de cada contenedor (Mounts → Name/Source). La solución cómoda es ponerles nombre (paso 13).
  • Paso 11 (tras parar mysql y mysql2): siguen los dos volúmenes. Parar un contenedor no toca sus volúmenes (el boletín pregunta por «los dos contenedores», pero se refiere a los volúmenes; los contenedores también siguen, detenidos).
  • Paso 12 (tras docker container rm mysql mysql2): docker volume ls sigue mostrando los dos volúmenes. Sobreviven a sus contenedores: los datos persisten aunque el contenedor ya no exista.
Desde Docker 23, docker volume prune solo borra por defecto los volúmenes anónimos sin usar; para incluir los que tienen nombre se añade -a. Nunca borra volúmenes que esté usando un contenedor.

3. Volúmenes con nombre y compartidos (pasos 13-16)

Poner nombre al volumen

docker container run -d --name mysql  -e MYSQL_ALLOW_EMPTY_PASSWORD=True -v mysql-db:/var/lib/mysql mysql
docker volume ls     # 14: aparece el volumen "mysql-db"
docker container run -d --name mysql3 -e MYSQL_ALLOW_EMPTY_PASSWORD=True -v mysql-db:/var/lib/mysql mysql
docker volume ls     # 16: ¿hay un volumen nuevo? No
  • -v mysql-db:/var/lib/mysql: a la izquierda el nombre del volumen, a la derecha la ruta dentro del contenedor.
  • Nombrarlo facilita identificarlo y asociarlo a su contenedor, y permite reutilizar los datos en otro contenedor.
  • Un volumen con nombre se crea solo si no existe; si ya existe, se monta el mismo. Así varios contenedores pueden compartir el mismo volumen.
  • Paso 16: no se crea un volumen nuevo; mysql3 usa el mysql-db que ya existía.
Docker deja compartir el volumen, pero dos servidores MySQL no pueden usar a la vez el mismo directorio de datos: lo normal es que mysql3 se detenga con un error de bloqueo de InnoDB. Compruébalo con docker container ls -a y docker container logs mysql3.

4. Bind mounting (pasos 17-20)

Servir con nginx una carpeta del host

cd /home/docker/EjemplosDocker/dockerfile-sample-2
docker container run -d --name nginx -p 80:80 -v $(pwd):/usr/share/nginx/html nginx
# navegador → http://localhost : ahora se sirve la web de dockerfile-sample-2
touch test.txt                                # crea el fichero vacío
echo "hola esto es una prueba" > test.txt     # escribe el texto (sobrescribe)
# navegador → http://localhost/test.txt : aparece al momento
  • $(pwd): la shell lo sustituye por la ruta del directorio actual del host antes de ejecutar docker. Como a la izquierda de : hay una ruta del host, es un bind mount.
  • /usr/share/nginx/html es la carpeta desde la que nginx sirve las páginas. El bind mount la sustituye por la carpeta del host, así que la página por defecto cambia por la de dockerfile-sample-2.
  • Los cambios en la carpeta del host se ven al instante dentro del contenedor (y al revés): no hace falta reiniciar el contenedor ni reconstruir la imagen.
  • > escribe en el fichero sustituyendo su contenido; >> añadiría al final.
Si sigue en marcha otro contenedor que publica el puerto 80 (por ejemplo, webhost de la práctica P2-1), -p 80:80 fallará: páralo antes.
Volumen = lo gestiona Docker; ideal para los datos de una aplicación (MySQL). Bind mount = carpeta concreta del host; ideal para editar ficheros y verlos al momento (la web de nginx).

Ideas clave para el examen

  • La capa de escritura del contenedor se pierde al borrarlo (no al pararlo): los datos importantes van en volúmenes o bind mounts.
  • Sin nombre → volumen anónimo (uno por contenedor, difícil de identificar). Con -v nombre:ruta → volumen con nombre, reutilizable y compartible.
  • Parar o borrar contenedores no borra sus volúmenes.
  • En Mounts: Source = ruta en el host; Destination = ruta en el contenedor.
  • Bind mount: ruta del host a la izquierda de :; los cambios se ven al momento.
