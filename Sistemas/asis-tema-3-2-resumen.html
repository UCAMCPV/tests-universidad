1. Active Directory y el servicio de directorio

Qué es Active Directory

Es la solución de directorio de Microsoft que permite centralizar la gestión de identidades de acceso de una empresa.

  • Se presenta en forma de rol del servidor.
  • Un servidor que alberga el rol de Active Directory se llama controlador de dominio (DC, Domain Controller).

AD DS, LDAP y el esquema

Los servicios de dominio de Active Directory (AD DS, Active Directory Domain Services) se basan en una arquitectura de directorio LDAP (Lightweight Directory Access Protocol).

  • El directorio registra información sobre usuarios, grupos, equipos, impresoras, contactos, carpetas compartidas y muchos otros tipos de objeto.
  • Cada tipo de objeto tiene un conjunto de atributos y propiedades definidos en el esquema de Active Directory.
  • El esquema define las clases de objetos y de atributos que puede contener la base de datos del directorio.

Las aplicaciones interrogan al directorio con el protocolo LDAP, basado en TCP/IP:

PuertoCuándo
TCP 389Al consultar un controlador de dominio simple
TCP 3268Al consultar un controlador de dominio que actúa como catálogo global
LDAP es el protocolo de acceso al directorio: 389 para un DC normal y 3268 para el catálogo global.

2. La base de datos: ntds.dit y la carpeta NTDS

Dónde está la base de datos

La base de datos de Active Directory es un archivo situado por defecto en %SYSTEMROOT%\NTDS\ntds.dit. Está en cada controlador de dominio.

La carpeta NTDS contiene además los registros de transacciones, archivos de log y archivos temporales que necesita Active Directory:

ArchivoPara qué sirveTamaño
ntds.ditLa base de datos de Active Directory. Está en cada controlador de dominio—
edb.chkPunto de control (checkpoint) de ntds.dit: registra las transacciones ejecutadas correctamente y permite saber si ya se han registrado en la base de datos—
edb.logÚltimas transacciones aún no registradas en la base de datos. Los cambios enviados a un DC se escriben primero aquí y después se integran en la base de datos10 MB fijos
edb000X.logArchivo auxiliar que almacena las transacciones destinadas a edb.log10 MB fijos
edbres00001.jrs y edbres00002.jrsReservan espacio de escritura en disco por si este se llena: AD sigue funcionando mientras el administrador hace el mantenimiento10 MB fijos cada uno
edbtmp.logTemporal que almacena información de las transacciones, de forma similar a edb.log10 MB fijos
temp.edbTemporal con la información de las transacciones durante el mantenimiento que compacta ntds.dit—
cambio enviado al DC ──► edb.log (primero) ──► ntds.dit (después)
                            ▲
            edb.chk: marca hasta dónde ya está guardado en ntds.dit
Los archivos de log y de reserva tienen un tamaño fijo de 10 MB. En la captura del documento la carpeta NTDS tiene además otros archivos (Api*) que el texto no comenta.

3. Administrar Active Directory

El servicio de Windows de AD DS

Al instalar el rol Servidor AD DS se crea un servicio de Windows llamado Servicios de dominio de Active Directory, con arranque automático. Esto facilita el mantenimiento de la base de datos: basta con detener ese servicio.

Detenerlo detiene también (el sistema avisa en el cuadro «Detener otros servicios»):

  • Centro de distribución de claves Kerberos (KDC).
  • Mensajería entre sitios.
  • Servidor DNS.
  • Replicación DFS.

Consolas de administración

  • Usuarios y equipos de Active Directory: la instalación del rol copia este complemento (en las herramientas administrativas o en una nueva MMC). También se abre con dsa.msc (símbolo del sistema, búsqueda de aplicaciones o ventana Ejecutar) o desde el menú Inicio de Windows Server 2016.
  • Las consolas se pueden instalar en un servidor sin Active Directory o en un puesto cliente (Windows 7, 8, 8.1 o 10) instalando RSAT (Remote Server Administration Tools).
  • Administrador del servidor: haciendo clic en AD DS desde el Panel se ven directamente los registros de eventos vinculados al directorio.

Centro de administración de Active Directory (ADAC)

Consola accesible desde Herramientas del Administrador del servidor y desde las herramientas administrativas de Windows Server 2016. Permite, entre otras cosas:

  • Administrar objetos usuario o equipo y unidades organizativas.
  • Elevar los niveles funcionales de dominio o de bosque.
  • Activar la papelera de reciclaje de Active Directory, que permite recuperar objetos eliminados por accidente desde un nuevo contenedor llamado Deleted Objects.
La papelera no tiene vuelta atrás: una vez activada no se puede eliminar (desactivar), y exige que el nivel funcional de todo el bosque sea como mínimo Windows Server 2008 R2.

La ventaja de ADAC es que se basa completamente en comandos PowerShell del módulo de Active Directory: cada acción de la interfaz genera, de forma transparente, comandos PowerShell que se pueden consultar en la sección Historial de Windows PowerShell.

Crear la UO «Carpetas compartidas» dentro de la UO NEXTINFO desde ADAC genera:

New-ADOrganizationalUnit -Name:"Carpetas compartidas"
    -Path:"OU=NEXTINFO,DC=nextinfo,DC=priv"
    -ProtectedFromAccidentalDeletion:$true -Server:"DC-01.nextinfo.priv"
Set-ADObject -Identity:"OU=Carpetas compartidas,OU=NEXTINFO,DC=nextinfo,DC=priv"
    -ProtectedFromAccidentalDeletion:$true -Server:"DC-01.nextinfo.priv"

4. Particiones y esquema

Las tres particiones lógicas

ParticiónContieneAlcance
EsquemaTodas las clases de objetos y atributos que se pueden crear en el directorioÚnica en el bosque; se replica en todos los controladores de dominio
ConfiguraciónInformación sobre los dominios, los sitios, la programación de las replicaciones y la topología del bosqueÚnica en el bosque; se replica en todos los controladores de dominio
DominioTodos los objetos que existen en un dominioUna por dominio: cada dominio tiene la suya

Extender y ver el esquema

  • El esquema es extensible: se puede modificar para añadir nuevos atributos o clases de objetos.
  • Modificarlo requiere una cuenta de administrador del grupo Administradores de esquema.
  • Para verlo se usa el complemento Esquema de Active Directory, que no está disponible por defecto: primero hay que registrar su dll y después agregarlo a una nueva consola MMC.
C:\> regsvr32 schmmgmt.dll
→ «DllRegisterServer se realizó correctamente en schmmgmt.dll»
→ mmc ▸ Agregar complemento ▸ Esquema de Active Directory

5. Gestión de identidades y acceso: Kerberos

Autenticación y permisos

Una de las funciones principales de AD DS es gestionar la autenticación y los permisos de acceso dentro de un dominio. Para ello, el controlador de dominio emplea las ACL (Access Control List) junto a un protocolo de autenticación como NTLM (NT Lan Manager) o Kerberos.

Autenticar a un usuario consiste en comprobar que la combinación de nombre de usuario y contraseña que da al conectarse al dominio es correcta.

Kerberos v5

  • Es el protocolo de autenticación predeterminado de Windows; Microsoft usa por defecto la versión 5.
  • Funciona con un sistema de tiques (también llamados tokens de acceso) y un intercambio de claves secretas protegidas con encriptación simétrica.
  • Al autenticarse, el usuario puede pedir un tique de acceso válido durante toda su sesión; con él accede a los distintos servicios (archivos, aplicaciones, impresión…) presentándolo.
  • Arquitectura: un cliente Kerberos en los equipos cliente y un servidor Kerberos en un controlador de dominio, con un KDC (Key Distribution Center, centro de distribución de claves).
  • El KDC autentica a los usuarios con un servidor de autenticación que distribuye los tokens de acceso TGT (Ticket Granting Ticket) y después distribuye los tiques de servicio TGS (Ticket Granting Service) para los distintos servicios del dominio.

Acceso a un servidor de archivos, paso a paso

  1. El usuario se autentica en el dominio; la información de conexión se registra en un controlador de dominio.
  2. El servidor Kerberos valida la información y le devuelve un token de acceso: el TGT.
  3. El servidor de autenticación emite una solicitud Kerberos presentando el TGT del usuario a un controlador de dominio.
  4. El controlador de dominio responde al usuario con un TGS.
  5. El usuario presenta el TGS al servidor de archivos, que valida su acceso.
  6. El usuario ya puede abrir los recursos del servidor de archivos.
CLIENTE ──1──► DC/KDC        (autenticación)
CLIENTE ◄─2─── DC/KDC        TGT
           3   DC ⇄ KDC      se presenta el TGT
CLIENTE ◄─4─── DC/KDC        TGS
CLIENTE ──5──► ARCHIVOS      presenta el TGS
CLIENTE ◄─6──► ARCHIVOS      acceso a los recursos
Primero el TGT (demuestra quién eres ante el dominio); con él se consigue el TGS (tique para un servicio concreto), que es lo que se presenta al servidor.

SPN (Service Principal Name)

  • Para usar la autenticación Kerberos hay que crear un nombre principal de servicio (SPN).
  • Se compone de una clase de servicio, un nombre de host y un puerto, y debe registrarse en una cuenta de usuario o en una cuenta de equipo predefinida (NetworkService o LocalSystem).
  • Con una cuenta integrada, el SPN se registra automáticamente; si el servicio se ejecuta con una cuenta de usuario de dominio, hay que registrarlo manualmente:
setspn -s http/<NombreDeServidor>.<NombreDeDominio>:<puerto> <CuentaDeUsuarioDeDominio>
Errata del documento: escribe http:/ (con dos puntos tras http) y deja un espacio antes de :<puerto>. El formato del SPN es clase/host:puerto, sin espacios.

6. Unidades organizativas

Qué son y con qué se administran

Los objetos de un dominio se almacenan en un contenedor llamado unidad organizativa (UO, en inglés OU, Organizational Unit), que organiza el conjunto de objetos mediante un árbol de carpetas.

Las UO se administran con:

  • El complemento Usuarios y equipos de Active Directory.
  • La consola Centro de administración de Active Directory.
  • La línea de comandos: el módulo Active Directory para Windows PowerShell o los comandos DS tradicionales de DOS.

Cuatro formas de crear una UO

HerramientaProcedimiento
Usuarios y equipos de ADAbrir la consola (herramientas de administración o dsa.msc) ▸ clic derecho sobre el dominio o una UO existente ▸ Nuevo ▸ Unidad organizativa ▸ escribir el nombre ▸ Aceptar
Centro de administración de ADAbrirlo desde las herramientas administrativas ▸ en Información general, seleccionar el dominio ▸ elegir la ubicación (dominio o UO) ▸ en la sección Tareas, Nuevo ▸ Unidad organizativa ▸ nombre ▸ Aceptar
Comandos DOS (en un DC)dsadd ou <DN de la unidad organizativa>
PowerShell (en un DC)Administrador del servidor ▸ Herramientas ▸ Módulo de Active Directory para Windows PowerShell ▸ New-ADOrganizationalUnit
La opción Proteger contenedor contra eliminación accidental viene marcada por defecto al crear una UO: la protege frente a operaciones nocivas o peligrosas.
C:\> dsadd ou OU=Grupos,OU=NEXTINFO,DC=NEXTINFO,DC=priv
dsadd correcto:OU=Grupos,OU=NEXTINFO,DC=NEXTINFO,DC=priv

PS C:\> New-ADOrganizationalUnit -Name Servidores -Path "OU=NEXTINFO,DC=Nextinfo,DC=priv"
           -ProtectedFromAccidentalDeletion:$true
  • El DN (nombre distinguido) se escribe desde el objeto hacia la raíz: primero la UO nueva (OU=Grupos), luego su UO padre (OU=NEXTINFO) y al final el dominio (DC=…,DC=priv).
  • En New-ADOrganizationalUnit, -Name es el nombre de la UO y -Path el contenedor en el que se crea.
Errata del documento: el segundo procedimiento gráfico empieza diciendo «consola Usuarios y equipos de Active Directory», pero los pasos que describe son los del Centro de administración de Active Directory.

Ideas clave para el examen

  • Servidor con el rol AD DS = controlador de dominio. AD DS se basa en LDAP: puerto 389 (DC) y 3268 (catálogo global).
  • Base de datos: %SYSTEMROOT%\NTDS\ntds.dit, en cada DC. Los cambios van primero a edb.log; edb.chk es el punto de control; los .jrs reservan espacio; temp.edb se usa al compactar.
  • Detener AD DS detiene KDC, Mensajería entre sitios, DNS y Replicación DFS.
  • dsa.msc = Usuarios y equipos; RSAT para tenerla en un cliente; ADAC = PowerShell por debajo + papelera irreversible (bosque ≥ WS 2008 R2, contenedor Deleted Objects).
  • Particiones: esquema y configuración únicas en el bosque; dominio, una por dominio. Esquema: Administradores de esquema y regsvr32 schmmgmt.dll.
  • Kerberos v5 por defecto: TGT → TGS → servicio. SPN = clase de servicio + host + puerto; manual con setspn -s si el servicio usa una cuenta de usuario de dominio.
  • UO: cuatro vías (Usuarios y equipos, ADAC, dsadd ou, New-ADOrganizationalUnit) y protección contra eliminación accidental marcada por defecto.
